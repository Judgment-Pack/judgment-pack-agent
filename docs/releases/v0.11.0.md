# v0.11.0

Release notes for v0.11.0. This document describes the release contents and the gates that must be satisfied before publication.
The package is `@judgment-pack/harness`. A completed release is expected to publish
its attested npm tarball and checksums and create the matching Go module tag
`go/v0.11.0` on the release commit for module
`github.com/Judgment-Pack/judgment-pack-agent/go`. The package version and lockfile identify v0.11.0. Publish only after the release procedure
verifies the package, checksums, attestations and matching Go module tag.

## Release scope

v0.11.0 contains versioned checkpoint/event/policy readers, task-aware plans,
repeated-tool controls, per-turn routing, optional usage budgets, retained history,
feedback and archive/capture APIs, and tool-taxonomy and dialect-authoring surfaces.
Release publication remains subject to the prerequisites below. The host migration details are in the [host upgrade guide](../upgrade/v0.11.0.md).

Archive1 is the retained-history archive shape introduced in v0.11.0; it has no
compatibility promise for unpublished archive prototypes. Imported archives are detached,
read-only display data and cannot resume or execute a run. v0.11.0 does not supply a
persistent host store or scheduler. ADR-0025's unattended-run build items
#223–#230 are assigned to v0.12.0 and are not claimed here.

## Host review before pinning

Upgrade readers before writing feature-bearing records. Feature-free checkpoint,
event and report outputs retain their existing formats; opt-in features may write
checkpoint 3, event 2, policy 2 or report 2 as described in the guide. Review the
storage ownership, archive read-only constraints and explicit per-feature defaults
before enabling a capability.

A durable root-author native invocation with an accepted Plan and conversational
controls (`AllowConversation` in Go, `allowConversation` in TypeScript) retains
checkpoint 3 / event 2 claim evidence before the provider call; see
[host preparation](../design/host-preparation.md) for the exact pause, release and
continuation requirements.

  This is the `retained-column/1` companion at `draft` maturity with explicit trusted

  but cannot authorize a new proposal or grant execution authority. The 48 TypeScript/Go calls against the published Runtime v0.39.0-alpha.2 release

  the publication evidence is recorded in [PR338](https://github.com/Judgment-Pack/judgment-pack-runtime/pull/338#issuecomment-6432852188).

  Its exact-source main CI passed all jobs in one attempt, PR 184 review recorded no
  findings, and its release workflow and published asset/attestation verification

  lifecycle fixtures for Core 0.2.0-draft and 0.3.0, including fresh signed fixture

  re-execution; 11 backward-consumer calls also passed against unchanged

  ([approval](https://github.com/Judgment-Pack/judgment-pack-agent/issues/192#issuecomment-6426997641)).

  changes, and when the exception expires. Separately record the exact release commit,
  npm audit coverage/result, Python dependency assessment, and current primary evidence;
  the offline fixture check is not a live advisory assessment.
- **Capture/export.** Optional transcript-v1 capture metadata and projection are
  implemented and paired focused-verified. Integrated CI, review and final release
  evidence are required;
  this does not claim live-provider comparison or whole-issue acceptance.
- **Scoped runner image exception.** The [maintainer approval](../security/v011-runner-image-exception.md)

## Live answer comparison

No live answer-quality, token-saving or monetary-cost result is claimed. For Agent
v0.11.0 only, the maintainer deferred #169 and the dependent live routed/unrouted
comparison on 2026-10-26 ([scope decision](../release-quality.md#v0110-scope-decision),
[issue comment](https://github.com/Judgment-Pack/judgment-pack-agent/issues/169#issuecomment-6421140155)).
The issue remains open and unscheduled. Desk may test the published release and
report bugs; the deferral applies only to Agent v0.11.0. It does not waive other
release gates. No Desk comparison requirement is asserted here.
