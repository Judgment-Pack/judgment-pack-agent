# v0.2.0

The second release of `@judgment-pack/harness`, as an attested package asset, after the Desk swapped onto v0.1.0 (judgment-pack-desk#516). It holds the remaining improvements of the `assistant-harness` set, each held by tests and mutation checks and reviewed in a clean-room round recorded on its pull request, and one clean-room review of the whole release diff recorded on the release-prep pull request. There is no registry package.

## What v0.2.0 holds

- #8, the context across a chat's turns (#33): a host may hand every run of a chat one `ChatContext` (run option `context.chat`); the ledger and the read cache then outlive a run and are cleared only by `dispose()`, keyed by content digest; an immutable read with the same arguments is served from the cache without a Runtime call, keyed by the tool, its arguments and, where the result depends on it, the Runtime's identity and version (`context.runtime`, a host tool's `contextPolicy.runtime`); a bounded index of the earlier turns' results goes into the new turn's first message, cut to the room left and never previewing the request. On the scripted two-turn chat the second turn fell from four requests and 102,963 bytes to one request and 21,231 bytes, with no repeated read. Nothing from one chat is reachable from another.
- #11, the harness side (#33): the contract states the memory recall rule a host applies on every wire (the first user turn's first text part not starting with `STATE_HEADER`); on the model wires a previewed prompt (with `currentRequest`) and a delegated child's objective keep that part; on the agent wire the rule holds where the prompt fits, and a previewed or delegated Codex prompt does not lead with the person's message (the previewed case is fixed in this release's pre-release batch); vectors per wire and a certification check on every certified leg; `memoryBytes` is freed only when the host says memory is off (`context.memory: false`); on or unsaid, it is kept.
- #10, the critic (#34): an allow-list (`validate`, `experimental_evaluate` in rehearsal, `get_schema`, `experimental_test_cases`, and the harness's own `read_window` and `search`) held at the session boundary before the gate, with a guardrail event for any other name; the critic compares rehearsal outcomes with the declared cases and the pack's tests (`run-event.json#/$defs/caseComparison`), the harness completing uncompared cases itself within the test tool's bounds; a critique with any uncompared case is marked `incomplete` and the proposal's verdict is never a plain "not refuted"; one default for both engines (the session's `adversarialReview`, otherwise off); the critic's requests and cost in its figures (`provenance.json#/$defs/criticFigures`).
- #25 (#34): the agent-engine certification leg compares its offer with the scenario's offer vector and sends a recorded `write_file` that must be refused at the gate; a gate admitting a sixth name now fails both certifications.
- #29 (#34): the Codex adapter gets one tool-free reformat run on a proposal that cannot be read; a turn clock that pauses is impossible under the bridge's ten-minute ephemeral thread and is recorded as an engine disagreement; a name the session serves but the run did not offer is refused before any call.
- #14 and #15, delegation (#35): `delegate_tasks` is an awaited tool call on the API engine, so a delegating turn is one parent run with native tool messages and no re-dump (on Codex the run still ends at the call and the next run receives the findings as a framed block, recorded as a disagreement); up to four batches per response within the shared budget with one request kept for the parent, and on Codex the tool is offered only while a child run and the parent's next run both remain; a finished child can be resumed by its task id; children receive references, not copied text, and share the parent's read cache; four closed profiles (`analyze`, `review`, `research`, `author-test` with the gate's six Runtime tools) each with a model, request and tool budgets and a time limit; concurrent children share `remaining − reserve`; a long child result is kept as head plus a `read_window` cursor; the twenty-call cap is stated to the model.
- #16, #17 and #18, delegation results (#39): a child's result is a report in its profile's shape (summary, findings, citations, open questions, confidence, not done); a child's question, proposal, delegation request or research-consent request returns as an open question with the task complete, and one more batch is allowed; a running child's text streams as `message_progress` with its task id; at its time limit a child returns what it wrote marked `partial`; one retry before the first byte for a 5xx other than 504 that carries the retryable class or the overload code; an identical task is reused within the chat only when the child made no counted tool call and only after its batch answer was delivered, and a Retry reuses unless the host sends `delegationReuse: false`; each child's record carries its model, requests, tool calls, tokens where the provider returns them, time to first byte and duration, and the parent's checkpoint carries the batch figures.
- The host answers one function per run with the connection, `modelsFor({connection, engine, family, model})` → `{critic?, child?, concurrentRequests?}`: a cheaper model for the critic and for children where the connection offers one, and the connection's concurrency (always one on Codex). `childModel` and `concurrentRequests` are not capability-record members.
- #12, the Codex cases (#39): the three injection cases run on the Codex engine as on the API engine.
- #13 (#35, #40): six certified scenarios run by both certifications: chat mode with host tools, delegation with a resume, memory on and off, plan mode, the correction loop with the critic, and a three-turn chat; plan mode's Runtime reads are the gate's ceiling less the evaluation and the test run.
- #36, #37 and #38 (#41): the Codex prompt heads the state and guidance it appends after the person's message with `STATE_HEADER`, so a host's recall rule cuts there, with a vector and a certification check; the Desk's 111 removed mutation rows live here as a bounded mutation-check workflow (changed-file rows and a sample on each pull request, the whole table weekly in shards), with tests for the four session rows and the two guards nothing covered; the conformance recorder is carried here with `conformance:record` and `conformance:verify`; provider options ride under the key the AI SDK names, with the reasoning-effort and parallel-tool-call options asserted on the wire and the deprecation warning failing the suite.
## What the Desk must do to adopt it

Recorded as judgment-pack-desk issues, to land with the Desk's pin of this release: #517 (the recall rule and the chat context, runtime identity and memory flag), #518 (`adversarialReview` where the pack pane ran the critic), #519 (the certification in the Desk's CI), #520 (the connection on every run, `modelsFor`, the Codex bridge's child model, the task view), #521 (child reports, open questions and figures, streamed text by task, capacity, Retry's reuse), #522 (a queue before the relay's slots) and #523 (the endpoint probe and keyless local endpoints).

## What it does not hold

the adapters of ADR-0001's steps 3 and 4, the Deep Agents JS adapter and the Go adapter, which follow in later releases; the findings of the pre-release batch's own review (#45) are LOW and follow with them

## Installing and verifying
