# v0.9.1 (draft)

Memory lifecycle reporting can revoke or expire a previously recalled identity after its host
deletes the text, including when prompt recall is disabled. Optional host lifecycle callbacks
carry only id, digest, kind and terminal state. Both runtimes validate complete answers atomically,
preserve concurrent proposals, refuse identity rewrites, contradictory recall and resurrection,
and retain the existing checkpoint/report shape and per-run prompt text.

## Fixed API request allowance

Hosts may set TypeScript `context.requestCap` or Go `Input.RequestCap` to an integer from 1
through 20. It is captured before setup and persisted as optional `checkpoint.requestCap`.
An explicit cap, including 20, is fixed: extension and inconsistent resume identity refuse.
Omitting it preserves legacy defaults and bounded grants. Native invocation counts do not accept
an API cap. Delegated API children receive their cap before initialization; zero remaining
allowance cannot create a child.

Capped checkpoints require compatible readers: an older open-record reader can ignore the
member and mistake a cap of 20 for an extendable allowance. Hosts must select the newest durable
checkpoint, supply the same independently trusted cap on resume, serialize admission and account
for transport retries. A durable claim precedes handoff; this does not promise globally exactly-once
delivery. Caught or ignored invalid `LimitTo` calls permanently refuse the context.

## Breaking input migrations

- `adversarialReview` (native `Run.Review`) is refused on presence, including false. Use `critic`
  / `Critic` with `on`, `off` or `auto`, or nested `policy.critic.default`.
- The flat `budget.json` policy-layer reader is retired. Move bounds under `policy.budget`,
  `criticDefault` to `policy.critic.default`, and `criticReasoningFloor` to `policy.critic.reasoningFloor`.
  Retired root members also refuse alongside canonical replacements.
- Bare-text memory answers, including empty text and native `MemoryForFunc`, are refused. Return
  closed `Memory[]` / use `MemoryRecordsForFunc`; null/nil/undefined supplies nothing.

Request-builder and checkpoint-controller source APIs also change. TypeScript request
builders read admitted values through `session.values`, select roles with `forRole` and
admitted model names with `withModel`; controller state reads are detached snapshots,
and updates use `controller.mutate`. Go request builders use the `RequestSession` getters
such as `ModelID`, `Family`, `AgentCapability`, `PolicyBinding`, `ResolvedCapabilities`,
`RuntimeTools` and `OfferedHostTools`. Go execution `State()` reads are detached; replace
writes through their returned values with `MutateCheckpoint`. These are source migrations;
these source migrations preserve wire and checkpoint member shapes; the fixed-cap option below
adds an optional checkpoint member.

## Upgrade

The Go module is `github.com/Judgment-Pack/judgment-pack-agent/go`. The release workflow
will create `go/v0.9.1` on the release commit. After publication, pin the module with
`go get github.com/Judgment-Pack/judgment-pack-agent/go@v0.9.1` and commit `go.sum`.

Migrate all three retired inputs before upgrading. Existing hosts without a lifecycle callback
remain compatible once those inputs are migrated. To report forgotten memory across resume,
implement optional `memoryLifecycle` / `MemoryLifecycleFunc` using retained canonical metadata;
do not retain deleted prose or modify checkpoint rows.
