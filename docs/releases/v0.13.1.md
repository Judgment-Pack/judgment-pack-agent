# v0.13.1

Release notes for v0.13.1. This document describes the release contents and the gates that
must be satisfied before publication. The package is `@judgment-pack/harness`. A completed
release publishes its attested npm tarball and checksums and creates the matching Go module tag
`go/v0.13.1` on the release commit for module `github.com/Judgment-Pack/judgment-pack-agent/go`.
The package version and lockfile identify v0.13.1. Publish only after the release procedure
verifies the package, checksums, attestations and matching Go module tag.

The host migration details are in the [host upgrade guide](../upgrade/v0.13.1.md).

## Why v0.13.1, and not v0.13.0

The v0.13.0 tag (commit `e8436e2`) was refused by the release evidence gate during a staged
hosted-image roll ([#332](https://github.com/Judgment-Pack/judgment-pack-agent/issues/332)) and
was never published: no release, package tarball or `go/v0.13.0` tag was made from it. A tag is
never moved or reused, so this release is v0.13.1.

v0.13.1 is v0.13.0's content, as the rest of these notes describe it, plus the gate change of
[#333](https://github.com/Judgment-Pack/judgment-pack-agent/pull/333). The evidence gate is now
devkit v0.15.0's. The mutation table's shards compare `release-os`: their `node` and `npm` must
equal the pins, and their image name, platform and OS release must be the release runner's, but
their image version is recorded and not compared ([CI evidence](../ci-evidence.md#the-tables-shards-compare-release-os-332)).
`dev.json` pins Node to the exact release 22.23.4, and every workflow that sets up Node installs that release.
`jpdev`, which runs the checks locally, selects an installed Node by that version, so developers
of this repository need Node 22.23.4 itself (`nvm install 22.23.4`), not another Node 22. Neither
change touches the package's source (`packages/harness`, `go/`).

## Release scope

v0.13.0 builds the rest of ADR-0025 (unattended runs), agent principals, and the fixes and
framing the reviews of those lines found. A host that uses none of the new features sees
v0.12.0's bytes on the wire and in its records, apart from the changes the upgrade guide states for every host (each section names its own), among them chat snapshot 2 with its one cold cache (#271), #328's refusal to resume a `complete` head, and, in Go, checkpoint 5 and event 3 (report 3 at its end) for a call held for approval whose arguments cannot say the model's text (#275).

- **Unattended runs.** Durable waits, attention events and the park/wake report (#224, #228,
  PR #264); deadlines, approval expiry, resume revalidation and run closure (#225, #227, #265,
  PRs #266 and #268); re-authorization waits (#226, PR #272); and the run leases kit's hardening,
  with a subclass of the reference effect host refused (#258, PR #280).
- **Agent principals** (#260, PRs #273, #276 and #288; ADR-0029). A run can act under a
  delegation chain from an issuing host. It is an opt-in.
- **The durable-write record and the approval-shown digest** (#275, PR #277; #278, PR #290;
  follow-ups PRs #296 and #301). A write is answered only from its own record, and an approval
  is bound to the digest of the text the approved call runs.
- **Read-cache keys and Runtime identity surrogates.** Only arguments their parsed form says
  exactly are cached (#271, PR #274). A lone UTF-16 surrogate in the Runtime identity or a
  read's arguments is refused or left unkeyed (#246, PR #270).
- **The retained-column selector at final Spec 0.3.0** (#269, PR #270).
- **Run-owned jobs**: the core, cancel, abandon and the batches (#229, PRs #294 and #306;
  #303 and #310, PR #316; #325, PR #326).
- **One durable goal** (#230, PR #313; #318, PR #321).
- **Enrollment framing** for Go hosts that enroll their offers (#289, PR #298).
- **`list_context` framing**: a page that shows text the package did not write is one data
  block (#302, PR #307).
- **Approved continuations that delegate, and host ids** under the package's own ids (#305,
  #311, PR #312).
- **A resume of a `complete` head** (#328). Fixed in this release: before it, resuming a run
  whose head said `complete` asked the model again and could act again, as at v0.12.0. Such a
  resume is now refused `RunComplete`, before any request, tool call or write. Three resumes of a
  complete head are kept, each borne out by the store: a job wait's continuation where the store
  holds that wait claimed at this head, a re-authorization claim's view while its grant is
  unspent, and a leg of the run's open objective. An execution a host holds itself, with no run
  store or through a `context.checkpoint` callback, is not refused: handed back when `complete`,
  it is still asked again and can act again. The [host upgrade guide](../upgrade/v0.13.1.md)
  states the rule.
- **CI.** Three race jobs, `go-race-a`, `go-race-b` and `go-race-c` (#254, PRs #282 and #291;
  #292, PR #295). The full mutation table runs nightly and by dispatch (#299, PR #300) in 28
  shards, at most 14 at a time (#281, PR #284; #322, PR #324), and counts only failures the
  mutant caused (#285, PR #287); two rows the full table missed are caught again (PR #319). The
  release evidence gate moved to devkit v0.13.0 (#239, #240, PR #267), then v0.14.0
  (PR #279), and then v0.15.0 (#332, PR #333; above).

No dependency file changed since v0.12.0: `go/go.mod`, `go/go.sum`, `package.json` and
`requirements-dev.txt` are identical, and `packages/harness/package.json` and
`package-lock.json` change only the package's version.

## Host review before pinning (upgrading from v0.12.0)

Read the [host upgrade guide](../upgrade/v0.13.1.md) for each migration. The points a host must
review are:

1. **Readers before writers.** Checkpoints 4, 5 and 6, event 3, lease 2, report 3 and chat
   snapshot 2 are refused by earlier readers (ADR-0024). Upgrade every reader of a store before a
   writer that can write them, and do not downgrade a host while it keeps them. The new records
   `run-wait`, `run-resume`, `run-reauth`, `run-job`, `run-goal` and `run-principal` are written
   only by the features that name them.
2. **The approval card and digest.** A host that builds an approval card or reference from a
   stored checkpoint or event must show `approvalShownArguments` and send `approvalShownDigest`
   with the decision. Until it does, approving a call whose record keeps its text is refused
   `ApprovalNotShown`, and nothing runs.
3. **Go `approval stale`.** A call a published release paused for approval, whose parsed form
   may differ from what the person saw, is refused `approval stale` in Go and nothing runs. Tell
   people a paused approval may need asking again.
4. **A cold read cache once.** Each immutable read a stored chat had cached runs once more after
   the upgrade.
5. **The effect-host kit.** It now fails the authority repeatedly at three points, and a
   TypeScript subclass of `ReferenceEffectHost` is refused at construction.
6. **Store obligations.** A store kind that hosts waits, jobs or goals must implement their ports
   with durable lifetimes and pass `runStoreWaitConformance`, `runStoreJobConformance` and
   `runStoreGoalConformance` (Go `CheckRunStoreWaitConformance`,
   `CheckRunStoreJobConformance`, `CheckRunStoreGoalConformance`).
7. **Gateway v0.24.0 for job action members.** A gateway source with job tools needs Gateway
   v0.24.0, the first release that accepts them.

The sibling releases the guide names are published: Gateway v0.24.0, Runtime v0.39.0 and Runner
v0.27.0.

## Known limitations, moved to v0.14.0

- **#304's remainder.** A child's time limit stops a task-steps run instead of failing the task.
  It is reported `cancelled` ("The response was stopped.") though nobody stopped it, it can emit
  two errors for one cause, and the child's durable commit time counts against the limit. The
  run fails closed, and its head stays `running`. Item 5 of #304 is #328, fixed in this release.
- **#309.** On the durable agent wire, the model is not told an approved call's result: the
  invocation that continues the response is the recorded request sent again. The act runs once.
  Under task steps, standalone and through the coordinator, the approved continuation stops
  (`stopped`, "no usable complete response"). After an answered approval and then a Plan pause,
  the Plan decision fails `HostOutcomeUnknown`.
- **#317.** A Plan decision whose continuation delegates stalls, and the head stays `running`.
- **#308.** A source's schema `enum`, `const`, property names and `required` entries reach the
  model unframed and unbounded in count.
- **#315.** Goal commands carry no fence and no credential (`actor` is a label), and
  `abandonGoal` cannot stop a terminal objective's jobs: the host calls `abandonJobs` itself.
- **#323 LOW-1.** The model can be told "cancel requested" when the effect host turned a thrown
  `cancel` into its own refusal.
- **#286.** Through the `vercel` engine on Gemini, a number past what a double holds runs as
  `null`, before the harness reads the arguments.

## Release prerequisites

- **Go dependency disclosure (#192).** [GO-2026-5932](https://vuln.go.dev/ID/GO-2026-5932.json)
  (`golang.org/x/crypto`, the OpenPGP family) and
  [GO-2026-5781](https://vuln.go.dev/ID/GO-2026-5781.json) (`rsc.io/pdf v0.1.1`) remain in the
  Go module graph. No dependency file changed since v0.12.0, so the retained modules and their
  owning paths are those of the v0.11.0 assessment. On 2026-11-03 the maintainer extended the
  exception to Agent v0.13.0 and go/v0.13.0 only
  ([decision](https://github.com/Judgment-Pack/judgment-pack-agent/issues/192#issuecomment-6612888267)).
  That tag was never published, and on 2026-11-04 the maintainer carried the extension over to
  Agent v0.13.1 and go/v0.13.1 instead, on unchanged terms
  ([carry-over](https://github.com/Judgment-Pack/judgment-pack-agent/issues/192#issuecomment-6629717027)). The condition: before the tag, a fresh assessment at the exact v0.13.1
  release commit must show that neither affected package is imported in the native package, test
  and generator closure, and that the official symbol scan reports no findings, posted on #192
  with the commit, the closure count and the scanner's output. If either check fails, the
  approval does not apply, nothing is tagged under it, and the decision returns to the
  maintainer. The scope is native Linux/amd64, CGO enabled, default build tags, Go 1.26.10. The
  expiry is unchanged: 2026-11-07 00:00 UTC. This is not a fix, a withdrawal or a safety claim.
  Other configurations and releases after v0.13.1 are not covered; replacing the dependency path
  is #192, on milestone v0.14.0. Reassess at expiry, and on any change to dependencies, configuration or advisory
  evidence.
- **Runner image exception.** None. The evidence gate has no exception member, and this
  release's exact-source CI evidence must satisfy the [evidence gate](../ci-evidence.md): exact
  runner and tool matching for the CI jobs, and for the mutation table's shards the release
  runner's image name, platform and OS release with `node` and `npm` at their pins (#333).
- **Release validation.** Before publication, record the exact release commit, the full required
  check summary, exact-head CI, the full mutation table (all 28 shards) of a dispatch run on main
  at that commit, the dependency audit for the candidate (the npm live check, Python and Go, each
  with its commit, time, coverage and dispositions), and final artifact and attestation
  verification. A version edit alone does not satisfy these gates.

## Live answer comparison

No live answer comparison has passed for this release, and no live answer-quality,
token-saving or monetary-cost result is claimed. For Agent v0.13.1 only, the live comparison is
deferred ([scope decision](../release-quality.md#v0131-scope-decision)): the maintainer deferred
it again for Agent v0.13.0 on 2026-11-03
([issue comment](https://github.com/Judgment-Pack/judgment-pack-agent/issues/169#issuecomment-6614430639)),
and carried the deferral over to Agent v0.13.1 instead on 2026-11-04, on unchanged terms
([carry-over](https://github.com/Judgment-Pack/judgment-pack-agent/issues/169#issuecomment-6629717633)).
This release changes model-visible text for hosts that use its new features: run-owned jobs,
cancel and abandon, goal commands, and the framing of `list_context` and enrollment. A host that
uses none of them sees v0.12.0's bytes, apart from the changes the upgrade guide states for every host (each section names its own), among them chat snapshot 2 with its one cold cache (#271), #328's refusal to resume a `complete` head, and, in Go, checkpoint 5 and event 3 (report 3 at its end) for a call held for approval whose arguments cannot say the model's text (#275) (corrections on #169: [first](https://github.com/Judgment-Pack/judgment-pack-agent/issues/169#issuecomment-6615531794), [second](https://github.com/Judgment-Pack/judgment-pack-agent/issues/169#issuecomment-6616419212), [third](https://github.com/Judgment-Pack/judgment-pack-agent/issues/169#issuecomment-6617403657)). #169 stays open on milestone v0.14.0. The Desk's
application-level comparison ([Desk #599](https://github.com/Judgment-Pack/judgment-pack-desk/issues/599))
remains the route. Routing stays off by default. Every other release gate remains in force, and
the deferral does not waive the comparison for later releases.
