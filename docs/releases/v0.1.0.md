# v0.1.0

The first release of `@judgment-pack/harness`, the agent harness behind Judgment Pack Desk, as an
attested package asset. It is the swap-ready release: a harness the Desk can install in place of
its in-tree assistant, pinned by digest in its component lock. There is no registry package.

## What the package is

The Desk's assistant loop, extracted with no behaviour change and held behind one wire contract
([ADR-0001](https://github.com/Judgment-Pack/judgment-pack-agent/blob/v0.1.0/docs/adr/0001-one-contract-many-adapters.md)): the context budget and ledger, execution
and planning, delegation, the memory client, the tool gate, the failure catalogue, and the host
module through which a host supplies what the package needs.

- The **Vercel AI SDK adapter** (`@judgment-pack/harness/vercel`), extracted as the Desk runs it
  today.
- The **Codex adapter** (`@judgment-pack/harness/codex`), the ChatGPT-subscription engine, as a
  second adapter of the same contract.
- The **wire contract** (`@judgment-pack/harness/contract` and `contract/`): language-neutral JSON
  schemas and vectors for run events, tool calls and results, approvals, failures, budgets and
  provenance.
- The **certification suite** (`@judgment-pack/harness/certification`), run against each adapter:
  `npm run certify -- --adapter <id>`. Both adapters pass it at this release.

What stays the host's does not move: the keyless model relay and key custody, the tool gate's
approvals, and the Runtime tools' rehearsal rule.

## What v0.1.0 holds

The milestone "v0.1.0: swap-in ready":

- #19, the wire contract extracted from the Desk's engine slot.
- #20, the Vercel AI SDK adapter, and the Codex adapter beside it.
- #21, the certification suite.
- #22, this package and its attested release.

And the first improvements from the audit the Desk's `assistant-harness` issues came from, each
held by tests and mutation checks and reviewed in a clean-room round recorded on its pull request:

- #1, one read is one result: every reading tool's window is held to the result limit, and a
  `read_window` tool pages a ledger entry by line or page with a cursor.
- #9, a stable prompt prefix: the changing parts of a prompt come after the history, the execution
  snapshot is sent once, Anthropic requests carry cache breakpoints, and one model is held per run.
  On the recorded scenario the share of each request that repeats the one before rose from about a
  fifth to about four fifths. The state's placement is an endpoint capability (`statePlacement`,
  `strictAlternation`), with a strict-alternation certification leg.
- #6, for the API engine: a finished answer is never lost. A proposal that cannot be read gets one
  reformat request, then the whole answer is delivered with its cause; a critic failure becomes a
  note on the proposal; a proposal may arrive through the `propose_pack` host tool as well as the
  fence. The Codex adapter's counterpart is #29.
- #2, the harness side: a request is retried only when the catalogue classes the refusal as refused
  and lists its code as an overload code, at most twice, honouring `Retry-After`, never after a
  response byte; a turn clock pauses a run as the allowance does; a tool call has a deadline the
  model can read. The relay's queue and idle bounds stay the host's.
- #7, the Runtime's test-cases tool: the gate's ceiling becomes six names, adding
  `experimental_test_cases`, which takes exactly `pack` and `matrix` within a byte bound and reads
  no project file; `test_conformance` and the saved-project tools stay refused by name. A per-turn
  cap on test calls, carried in the checkpoint, keeps a test-fix-retest loop from spending the
  allowance.
- #3, the failure paths that were never exercised: a connection dropped before and after the first
  byte, a stall past the idle bound, a context-length refusal, a Runtime socket dropped during a tool
  call, and a whole JSON answer in place of a stream, each with its class, its recovery, a checkpoint
  that survives, and what Retry does. The decision not to shrink and resend on a context-length
  refusal is recorded in `docs/design/ai-error-handling.md`.
- #12, the harness side: every reading tool's result reaches the model framed on both ends with a
  per-run random marker, delivered on purpose as a data block, and the instructions carry the rule
  that retrieved text is data. Injection tests show a page cannot reach an unoffered tool, and that
  for a `propose_*` tool the boundary is the review card. The Codex cases stay open under #12.
- #5, with #4's harness side: a `search` tool with a bounded, linear-time regex engine over the
  ledger and the attachments the host exposes, its compilation and per-line work charged against
  stated bounds, line numbers and a default window on `read_window`, image parts for models whose
  capability record says vision and the host's text rendering otherwise, a per-request cap on image
  count and bytes, and an image that cannot be shown always says why; and the provider capability record (`contract/schemas/capability.json`): context
  window, output cap, native and parallel tool calls, vision, the reasoning parameter's kind,
  streaming quirks and tool-schema narrowing, with three family defaults the host overrides per
  endpoint, and a JSON-in-text tool-call fallback for an endpoint without native tool calls. The
  endpoint probe, keyless local endpoints and the Azure branch stay the host's under #4.
Parity with the Desk's harness is held by the certification suite at this release; the
improvements above change what a model is sent and what it may do, and the Desk's swap adopts them
with the package.

## What it does not hold

The remaining improvements of the `assistant-harness` set follow in later releases: #2's relay queue, #4's endpoint probe, keyless local endpoints and the Azure branch, #8, #10, #11, #12's Codex cases, and the delegation set #13 to #18.
Also not held: #25, the certification gap around the gate's ceiling on the agent-engine leg, and
#29, the Codex adapter's reformat turn and turn clock.

## Installing and verifying

Install the tarball from this release and pin it by the digest in `checksums.txt`. Verify the
attestation as [`docs/releasing.md`](https://github.com/Judgment-Pack/judgment-pack-agent/blob/v0.1.0/docs/releasing.md) describes before pinning.
