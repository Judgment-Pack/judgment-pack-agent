## The agent capability in Go (ADR-0007, agent#67)

- **Two capabilities, one coordinator.** `adapter.Run` gains `Agent`, the agent capability beside
  the model capability: a host-owned provider-run function (`adapter.AgentRun`) that takes the
  published agent request (prompt, instructions, tools by name, effort, phase, model) and answers
  its events and tool calls through callbacks; no endpoint address, key or credential crosses. Its
  adapter is `go/adapter/agent`, on the `codex` engine's lifecycle, its prompt built by the one
  assembly ADR-0005 made canonical. `delegate.With` drives both capabilities.
- **Handoff and continuation.** A `delegate_tasks` call ends the parent's invocation; once the host's
  function has returned, the batch's children run one at a time on the account, and a new
  invocation continues with the call's exact result. Each transition is written into the
  checkpoint's new `handoff` member and acknowledged by the host's durable callback before the next
  invocation; a restored checkpoint continues where it stood and dispatches nothing again.
- **Accounting.** At most five agent runs a response, the continuation's room reserved before a
  batch; `agentRuns` in the figures; no model-request or token figure invented.
- **Contract.** `checkpoint.json` gains `handoff` (`$defs/handoff`, closed); `run-event.json`'s
  `delegation_requested` gains an optional `callId`; vector `delegation/handoff.json`.
- **Certification.** `go/certification` gains the agent checks with a fake exclusive account and the
  `AgentHost` seam a host certifies its own bridge with (`certification.CertifyAgent`);
  `go/cmd/harness-check` runs them on the stand-in and says so. `parity.json` maps the three agent
  checks the TypeScript suite also makes and lists the package's own.
