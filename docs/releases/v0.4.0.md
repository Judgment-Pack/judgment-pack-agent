# v0.4.0

The fourth release of `@judgment-pack/harness`, as an attested package asset and a Go module tagged by the release workflow, after the Desk's decision to run its assistant in its own Go server on the package's adapters (judgment-pack-desk#536, #537). It holds the decisions the Desk's swap needed: one assembler of the prompt, provider-managed delegation in Go, and the contract for tools from outside the Runtime. Each change but the three action bumps was reviewed in a clean-room round recorded on its pull request, and the whole release diff in one clean-room review recorded on the release-prep pull request. There is no registry package.

## What v0.4.0 holds

- **ADR-0005, the prompt is the adapter's** (#68; decides ADR-0002): every engine assembles the whole request in one layered order and the relay adds nothing; the host supplies three parts through injection points — `brief()`, `memoryFor(query)` (asked once per run) and `projectInstructions()` (the person's per-project block, the lowest-rank instructions, bounded by `projectInstructionsBytes`); the recall-rule machinery of v0.2.0 is removed; each request's sha256 digest is recorded in the checkpoint (`provenance.json#/$defs/promptDigest`); a project block that tries to lift the data rule or name a tool changes nothing the gate admits, certified on the vercel, codex and deepagents engines and the Go `eino` adapter. The order as sent is stated beneath the decision's diagram.
- **The release workflow tags the Go module** (#64): `go/vX.Y.Z` on the release commit after the publish, so `go get github.com/Judgment-Pack/judgment-pack-agent/go@vX.Y.Z` resolves at release time (v0.3.0's tag was pushed by hand); the delegation-concurrency certification check counts with a barrier instead of a timing window; an unoffered call's refusal keeps a detail's ellipsis.
- **ADR-0007, provider-managed delegation in Go** (#70): the Go adapter interface gains the agent capability beside the model capability — a host-owned provider-run function with no key, address or network path; on it a `delegate_tasks` call ends the parent's invocation and releases the exclusive account, children run one at a time, and the parent continues in a new bounded invocation with the exact call result; invocations are counted against `turn.MaxAgentRuns` with the continuation's room reserved and no model-request or token figure invented; every step is checkpointed and acknowledged before the next dispatch, and a restart repeats no committed operation; an invocation that reached any callback is never retried; a fake exclusive account certifies the lifecycle with a proof against the naïve synchronous wrapper, and a host certifies its own bridge through the `AgentHost` seam with `CertifyAgent` (`harness-check` says when it ran the package's stand-in only).
- **ADR-0006, tool sources** (#72): tools from outside the Runtime — gateway connections, public MCP servers, custom tools — reach the model as host tools the host declares and executes, never the package; each declaration carries a source record (kind, id, trust class, version or pinned tool-list digest, the gateway's receipt on results) that rides on every `tool_call`/`tool_result` and into the checkpoint's per-source figures; wire names are mapped stably into the providers' `[A-Za-z0-9_-]{1,64}` with collisions and reserved names withheld; an external tool is `act` with approval required unless the host declares it a read or a proposal, or declares `approval: none` on it, and a `propose` never runs; descriptions are bounded and framed as text, and an MCP server whose tool list leaves its pinned digest is withheld until re-approved; a schema budget per run with catalogue-then-load (`load_tool`) keeps the stable prefix; certified by a scenario with a scripted external server on the vercel, codex and deepagents engines and the Go `eino` adapter; the Go agent capability is certified on the delegation scenario and its agent checks. The review's remaining rows are #73, fixed in this release's pre-release batch; a run-level approval pause is #74.
- **The Runtime's prompt cached on Anthropic; the reserves retired** (#69, #75): a third `cache_control` breakpoint on the first user turn's text part, placed under `trailing-user` placement where the prefix before it is stable (under `system-tail`, the placement with a thinking tier on or strict alternation, the state sits in the system text and no third breakpoint is placed); the placement check asserts the count each placement expects on the vercel, deepagents and Go encoders. The brief and memory reserves no longer come off the input allowance: the parts are counted once where they sit, so the allowance grows by up to 12,000 bytes (8,000 with memory off), stated as a number in the allowance tests. `contextPolicy`/`ContextPolicy` lose their `memory` argument and `budget/memory.json` is gone: a TypeScript or Go caller still passing it no longer compiles.
- **The pre-release batch** (#77; closes #73 and #76): the source gate's calls-per-turn bound claimed before any await and returned on a refusal, held under twenty concurrent calls; descriptive text inside an external schema (property descriptions, titles, enum strings) framed and bounded on the offer, an enum or const over 64 bytes dropped rather than framed; the catalogue bounded by count and bytes with a guardrail for the rest; delegated children share the parent's source gate so a child's calls count against the turn and reach the parent's report; the approval reader receives the call's name, tool, source and arguments; receipt and `proposed` marks keyed by call id, the abort-after-approval path included; Go narrows a loaded schema by the capability record; a catalogued tool's arguments are checked against its loaded schema before the host executes; the four uncarried schema members now carried by vectors and the members probe; a Plan-mode case with declared sources (only the read is offered); the critic's requests checked for the run's host parts in both languages; the Go agent capability certified on the tool-sources scenario and a project check (it did not count a refused unoffered name in the Runtime's row; fixed); ten mutation-table rows added, each caught.### Also recorded by the pull requests that landed

- **Two capabilities, one coordinator.** `adapter.Run` gains `Agent`, the agent capability beside the model capability: a host-owned provider-run function (`adapter.AgentRun`) that takes the published agent request (prompt, instructions, tools by name, effort, phase, model) and answers its events and tool calls through callbacks; no endpoint address, key or credential crosses. Its adapter is `go/adapter/agent`, on the `codex` engine's lifecycle, its prompt built by the one assembly ADR-0005 made canonical. `delegate.With` drives both capabilities.
- **Handoff and continuation.** A `delegate_tasks` call ends the parent's invocation; once the host's function has returned, the batch's children run one at a time on the account, and a new invocation continues with the call's exact result. Each transition is written into the checkpoint's new `handoff` member and acknowledged by the host's durable callback before the next invocation. A restored checkpoint continues where it stood on the person's explicit continuation: a child it shows running is never dispatched again, a restored `answered` or `continued` handoff starts the parent's continuation again, as any restored parent run starts again, and committed operations are not repeated.
- **Accounting.** At most five agent runs a response, the continuation's room reserved before a batch; `agentRuns` in the figures; no model-request or token figure invented.
- **Contract.** `checkpoint.json` gains `handoff` (`$defs/handoff`, closed); `run-event.json`'s `delegation_requested` gains an optional `callId`; vector `delegation/handoff.json`.
- **Certification.** `go/certification` gains the agent checks with a fake exclusive account and the `AgentHost` seam a host certifies its own bridge with (`certification.CertifyAgent`); `go/cmd/harness-check` runs them on the stand-in and says so. `parity.json` maps the agent checks the TypeScript suite also makes and lists the package's own (thirty after the pre-release batch, #77).

## What the Desk must do to adopt it

judgment-pack-desk#546 (answer the three prompt parts, remove the server's prompt reading, the per-project instructions form), #537 (the swap's binding: the brief, memory and instructions as injection points; the agent capability bound to the Desk's Codex bridge) and #548 (tool sources: the custom-tool and MCP-server forms, source provenance in the report); #529 (the approval reader held to the vector) and #533 remain.

## What it does not hold

#71 (the agent capability's `modelRequests` made optional) and #74 (a run-level approval pause); the Desk's adoption (judgment-pack-desk#546, #548, #537).

## Installing and verifying

Install the tarball from this release and pin it by the digest in `checksums.txt`; the Go module by `go get github.com/Judgment-Pack/judgment-pack-agent/go@v0.4.0` with `go.sum` committed. Verify the attestation as [`docs/releasing.md`](https://github.com/Judgment-Pack/judgment-pack-agent/blob/v0.4.0/docs/releasing.md) describes before pinning.
