# v0.9.0

A release of `@judgment-pack/harness`, as an attested package asset and a Go module tagged by the release workflow. One contract change.

Install the tarball from this release and pin it by the digest in `checksums.txt`; the Go module by `go get github.com/Judgment-Pack/judgment-pack-agent/go@v0.9.0` with `go.sum` committed.

## What v0.9.0 holds

- **An omitted reasoning preference means the model's default, and stays omitted** (#142, pull requests #145 and #147; amends ADR-0011, ADR-0012 and ADR-0016). v0.8.x turned an omitted native author effort into an explicit `none`, which a host whose discovered model does not advertise `none` rightly refused. Now an omitted `models.<role>.reasoning` resolves to no value and the provider request omits the effort member, for the model author, the model critic, the agent author, the fallback and delegated child runs, in TypeScript and Go; `none` is only ever an explicit layer's choice, checked like any other value.
- **Provenance.** The resolved member carries `source` (`layer`, `model-default`, `discovered`), recorded by the `policy_resolved` event and the checkpoint, so a resumed run rebuilds the same request bytes.
- **Optional host discovery.** A host that knows the selected model's advertised set may supply it (`models.<role>.discovered.reasoning: {default, supported}`) before admission: an omitted preference then takes the advertised default, and an explicit chat or project value outside the set is refused before any generation, never replaced.
- **A table value is a default, not a preference** (pull request #147, from the release review). A reasoning value that comes from the policy table, the compactor's `low` included, stays when the model advertises it; otherwise it resolves to the discovered default with `source: discovered`, or stays omitted with `source: model-default` when discovery advertises no default. It never causes a refusal the host did not write.

## Unchanged

Precedence (chat over project over table), the wire contract's other members, every other ADR.

Without discovery, v0.9.0 admits every policy and session case that a 14-case comparison against v0.8.1 admitted, including run-only child and sub-agent `off` and `none` values with or without project authorization, and delegated profile and declared sub-agent roles. An omitted author preference now leaves the request member absent; an author preference that was set produces the same request member. Known author tiers keep their existing ceiling.

## Compatibility

Upgrade is supported: v0.9.0 reads v0.8.1 policy members and checkpoints, treating a historical member without `source` as layer-supplied. Downgrade is asymmetric because v0.9.0 records may carry `source`: v0.8.1's closed Go decoder rejects those members, while its TypeScript checkpoint reader accepts them. Do not run v0.8.1 readers against v0.9.0 checkpoints.

## The supported way to consume the package

Through a bundler. Native Node ESM import is tracked as #143 and is not part of this release.
