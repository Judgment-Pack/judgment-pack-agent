# v0.15.0

Release notes for v0.15.0. This document describes the release contents and the gates that
must be satisfied before publication. The package is `@judgment-pack/harness`. A completed
release publishes its attested npm tarball and checksums and creates the matching Go module tag
`go/v0.15.0` on the release commit for module `github.com/Judgment-Pack/judgment-pack-agent/go`.
The package version and lockfile identify v0.15.0. Publish only after the release procedure
verifies the package, checksums, attestations and matching Go module tag.

The host migration details are in the [host upgrade guide](../upgrade/v0.15.0.md), which
carries every row of the v0.14.0 guide. Apply it from v0.13.2.

## Why v0.15.0 holds v0.14.0

No v0.14.0 was tagged. The maintainer folded the v0.14.0 milestone into this release, so
v0.15.0 is the first release after v0.13.2. Its notes have two parts: the v0.14.0 milestone's
work, then the work of v0.15.0 itself. A host on v0.13.2 upgrades straight to v0.15.0.

## The v0.14.0 milestone

- **The durable agent wire** (#309, #317, PR #354). An approved call's result reaches the model
  in the continuation's data block, which now ends with `decidedAt`. Under task steps the
  approved continuation goes on to the end, and a Plan decision goes on after an approval pause.
  A Plan decision whose continuation delegates no longer stalls.
- **Goal commands carry a worker's fence** (#315, PR #359; #361 and #362, PR #366; #368, PR
  #369). A command sent through a displaced worker's view is refused `LeaseRefused`. The goal
  conformance kits hold a host store to the fence rules.
- **Successor runs** (#340, #341, PR #355; #362, PR #366). A successor carries the approved
  allowance, a claimed question wait continues a complete head, and a store value that hides the
  lease, wait or deadline ports is refused, unless it declares itself unleased.
- **The record guard** (#343, PR #350; #352, PR #365; #367, PR #370). A durable result, a
  Runtime read, the chat read cache, `handoff.answer` and a failure's detail are stored in the
  form the guard leaves of them. A detail is read whole before it is cut.
- **A source's schema words** (#308, PR #356). A source's `enum`, `const`, property names and
  `required` entries are kept as written only up to a bound. Past it the source is a catalogue.
- **Approval and engine fixes.** A custom source's ask is saved paused before the provider stops
  (#342, PR #346). A Runtime action's ask is saved on the model engines (#349, PR #360). A critic
  and an author-test child can rehearse an acting evaluation (#344, PR #353). The job batch's
  LOWs are fixed (#323, PR #360).
- **Records and tooling.** A checkpoint with `retainUntil` and no schema is refused, not a panic
  (#358, PR #363). The certification suite reads `runtime.json` from any directory (#345, PR
  #347). The mutation runner reports a mutant that breaks loading as BROKEN, not NOT CAUGHT
  (#320, PR #347), and its release help has three fixes (#348, PR #363). CI checks that setup-node
  runs first (#334, PR #347), and the release gate compares the release-os pins at capture (#338).
  The job tests' binary is split in two, with a fourth race leg (PR #364).
- **Undici.** The patched Undici 7.30.2 and 8.12.4 are required (PR #351).

## v0.15.0

### Delegated runs (#373, PR #378)

- **ES256 delegation statements.** A link may be signed with a P-256 key and hold `alg: "ES256"`,
  verified at low S. A chain may mix Ed25519 and ES256 links, and Ed25519 links verify exactly as
  before.
- **Pinned keys carry their algorithm.** `ContextInput.principal.keys` accepts
  `{"alg": "ES256", "key": <66 hex>}` beside the unchanged 64-hex Ed25519 form. The algorithm
  comes from the pin, never from a key's length.
- **A chain bound to one scope identifier.** A root may hold `scope.scopeId`, which every link
  repeats. Each gateway call is then sent with that identifier. A source mapped to another
  identifier, or to none, is refused `scope-id-mismatch` before the call leaves the harness, and
  a verified receipt of another scope is withheld. Under an unbound chain, a source mapped to an
  identifier is refused the same way, and the executor's context holds `scope: null`.
- **Credentials.** The host's executor sends the gateway credential. The library's own seam is
  `bindModelCall`, which reads `sessionBearer()` for each request.
- The specification's frozen statement cases are copied under `contract/testdata/principal/`
  (PR #382). Their citation names the specification's merge commit (PR #383).

### Admission read version "2" and the skill-load read (ADR-0030, PR #381)

- A host names the admission read version for each issuing host: `RunPrincipal.ReadVersions`
  (Go) and `readVersions` (TypeScript). "1" is the default, and its reads are unchanged byte for
  byte.
- At "2", a call read carries `call.version`, the approved snapshot's `descriptorDigest` or
  null, and `call.skills`, the run's loaded skills. The new answers are `tool-version-refused`,
  `skill-refused`, `read-version-unsupported` and `read-malformed`.
- A skill-load read goes through the `SkillLoad` / `skillLoad` port before the checkpoint write.
  A refusal is charged to `skillsPerRun` and writes a `delegation refused` guardrail, and the
  run goes on.
- The descriptor snapshot readers take gateway snapshot versions 3 and 4, at either read
  version.
- **Go, a source-level break.** `PrincipalAdmissionCall` gains `Skills` and is no longer
  comparable with `==`. `AdmitPrincipalStanding`, `AdmitPrincipalRuntimeCall` and `NarrowChild`
  each gain a `skills` parameter.
- The specification's `conformance/delegation/admission-reads.json` is copied, pinned by SHA-256
  and cited. Every case runs in Go and TypeScript.

### Toolchain and dependencies

- **Go 1.26.11** (PR #384). The pinned Go release moves from 1.26.10 to 1.26.11.
  `golang.org/x/crypto` moves to v0.59.0, which clears
  [GO-2026-5932](https://vuln.go.dev/ID/GO-2026-5932.json) and
  [GO-2026-6859](https://vuln.go.dev/ID/GO-2026-6859.json). `golang.org/x/arch` moves to v0.33.0,
  and with it x/mod, x/sys, x/text, x/sync, x/term and x/tools.
- **A new module in the graph.** `github.com/ledongthuc/pdf` enters the module graph with an
  "unknown" license and no origin evidence. It is graph-only: no package of it is in the build or
  test closure, and removing the path that brings it is
  [#386](https://github.com/Judgment-Pack/judgment-pack-agent/issues/386). It is another PDF
  parser, so any advisory against it gets its own decision under the
  [dependency policy](../security/dependency-policy.md). The standing exception below does not
  cover it.
- **hono and @hono/node-server** (PR #380) move to 4.13.16 and 2.1.6, clearing
  GHSA-3gg2-335m-rxc6, GHSA-46wx-v44x-9hh2, GHSA-4h7h-rv7c-7m2v, GHSA-4m76-xfj5-7975,
  GHSA-h7mg-cq63-vhpq, GHSA-jpvv-r467-5p4w and GHSA-qv5m-9pm6-hqp3.
- **The advisory exception gate** (PR #387). A new CI check, `advisory-exceptions`, holds each
  standing advisory exception to its conditions at the commit. It runs fresh on every push, is
  never reused, and the release admits only exact-commit CI where it passed.

## Known limitations, moved to v0.16.0

- **#304's remainder.** A child's time limit stops a task-steps run instead of failing the task,
  and reports itself as a person's stop.
- **#286.** Through the `vercel` engine on Gemini, a number past what a double holds runs as
  `null` before the harness reads the arguments.

## Release prerequisites

- **Go dependency disclosure (#192).** [GO-2026-5781](https://vuln.go.dev/ID/GO-2026-5781.json)
  (`rsc.io/pdf`) is under a standing exception that the maintainer bound to conditions, not to a
  date ([decision](https://github.com/Judgment-Pack/judgment-pack-agent/issues/192#issuecomment-7106596867);
  [policy](../security/dependency-policy.md#standing-exception-go-2026-5781-rsciopdf)). It holds
  only while three things are true at the release commit, for linux, darwin and windows on amd64
  and arm64:
  - `rsc.io/pdf` is absent from `go list -deps -test ./...`;
  - no package imports it, including files the build leaves out;
  - govulncheck, run with `-test` under the pinned Go, reports no finding of it at any level.

  The `advisory-exceptions` check holds these. If any fails, the release is refused and the
  exception returns to the maintainer. This is not a fix or a safety claim. Removing the path is
  #386, on milestone v0.16.0.
- **Runner image exception.** None. This release's exact-source CI evidence must satisfy the
  [evidence gate](../ci-evidence.md).
- **Release validation.** Before publication, record:
  - the exact release commit;
  - the full required check summary, `advisory-exceptions` included;
  - exact-head CI;
  - the full mutation table of a dispatch run on main at that commit;
  - the dependency audit for the candidate;
  - final artifact and attestation verification.

  A version edit alone does not satisfy these gates.
