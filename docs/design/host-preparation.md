# Preparing a resumed Go host run

Two package boundaries have different positions in the host lifecycle. Apply a pending canonical Plan decision before opening Runtime. Enroll the final contextual tool declarations after the actual contextual session has resolved its policy and before provider or tool dispatch.

For a paused Plan departure, load the exact saved execution and supply the original accepted Plan, its live-reference resolver, the person's `Input.Approval`, and the pending current and candidate revisions. Call `runcontext.PreparePlanDecision(ctx, input, runcontext.PlanDecisionExpectation{Revision: current, CandidateRevision: candidate})` before Runtime bootstrap. Use the returned `Input` for the subsequent adapter run and deliver the returned acknowledged event once. Its `Approval` is consumed. Preparation opens no Session or Chat turn and performs no session-policy resolution; the actual adapter later performs its one normal context construction and policy resolution. The resolver and authorization callbacks are trusted host capabilities; this is not an enforced no-I/O sandbox.

Preparation uses the original admitted root writer, its original scope and its exact RunStore CAS/receipt boundary. It validates the pending purpose, call, both revisions, original accepted content and current references. One transaction acknowledges the decision event and running checkpoint. Only Plan, Plan state, explanation, status and digest change: raw prior journal members, completed operations, observations, grants, policy, retention and lineage remain retained. Normal execution recovery of outstanding claims remains a later concern. A concurrent writer update refuses the stale decision. A simultaneous pending tool approval refuses. Missing or malformed retained output/records policy refuses rather than supplying defaults. An event awaiting publication requires an actual publisher.

A lost acknowledgement returns `StorageOutcomeUnknown` and closes that writer to further publication. Read the retained RunStore checkpoint/events to reconcile whether the decision committed. Never automatically replay the decision. Reusing the original pending input after acknowledgement refuses. There is no prepared Session or reusable initialization handle: pass the acknowledged input, without `Approval`, to the actual adapter. This consumes the decision exactly once; the host retains responsibility for one-delivery admission and any distinct durable action receipt. Arbitrary reuse of a completed adapter input is not newly authorized. Existing request, connection, phase, source and policy validation still applies; preparation adds no grants, actions or source authority.

Checkpoint 2 and 3 are admitted for this transition. A current task-bearing decision reconciles the retained schedule through the package's existing rules: held claims and child bindings survive, and the result remains checkpoint 3 with one event 2 decision. The native delegation coordinator pins its original invocation limit and child reserve in `planState.taskCoordinator` before first physical admission. This pin is distinct from the host's `taskEnvelope`; a restart must reattach the exact original coordinator binding and cannot supply a replacement ceiling.

A durable root-author native invocation with an accepted Plan and `AllowConversation` enabled also retains a checkpoint 3 / event 2 claim record before the provider call. If the actual package tool pauses that invocation for a Plan decision, its callback drain and the host's exact invocation release acknowledgement permit the original writer to retain `durable.dispatches[].planPause` and a full paused checkpoint event in the same CAS. The original dispatch remains `unknown`, including its failure and budget holds. An acknowledged explicit decision retains `nativeInvocation` in its decision row and event; it never marks the earlier invocation successful or grants allowance. Before a fresh invocation, the package verifies the ordered original claim, released pause and decision against the basic RunStore event journal and pinned current head. Missing, expired, truncated or inconsistent evidence, uncertain acknowledgement or another unknown invocation refuses continuation. A permitted next invocation gets a new identity and consumes the unchanged ordinary allowance. No optional HistoryRunStore interface is required.

Native calls without an accepted Plan or without conversational controls, and child, critic, reformat and non-durable calls, keep their previous record/event behavior. An accepted-Plan invocation which finishes normally does not acquire a new release requirement; the release proof is required for the actual Plan-pause continuation. Routing and delegation compose their existing release owners with this proof rather than replacing them. TypeScript's normal contextual continuation uses the same shared checkpoint/event additions and original-writer safeguards; the decision-before-bootstrap preparation API remains Go-specific.

After the host's ordinary Runtime handshake and domain-tool registration, set `adapter.Run.EnrollContext`. Both Eino and the native agent adapter use `runcontext.ContextualSessionWithEnrollment` to call it once with an `adapter.ContextOffer` made from the actual final `Session.HostTools`. The callback runs after the complete declarations are assembled, before construction resumes any already approved host action through `continueApproval`, and before provider dispatch. The original `ContextualSession` entry point delegates without a callback for compatibility. It carries execution/task identity, mode, an opaque acknowledgement ID and detached complete declarations, including policy-dependent schemas and configured draft, catalogue, skill, review and execution controls. It carries no execution closures. The host acknowledges with `hostGate.EnrollContext(offer.ID, offer.HostTools)` and returns that error. The adapter verifies the exact acknowledgement before opening its boundary or invoking a provider/tool path. A callback error, missing acknowledgement, mutation, duplicate acknowledgement, malformed declaration or collision refuses dispatch.

The gate reconciles an already registered host declaration only when its complete serialized metadata is identical; it cannot replace an inconsistent declaration or drop an existing one. Remove legacy guessed or name-only contextual placeholders from initial gate registration. Domain execution closures remain in the actual Session; enrollment changes metadata only. The Runtime offer stays fixed. Work, Plan, child, critic and reformat restrictions remain in force; child profiles and parent restrictions are retained, and an existing critic/reformat narrowing cannot be widened by enrollment. Exact names are required, including case and prefixes.

The callback remains optional for existing hosts. Its absence preserves legacy behavior and is not proof of final-offer enrollment. The certification `boundaryTools` fixture now uses real package constructors, including `complete_plan_step`, but its fixed default policy declarations do not replace actual-session enrollment. The enrollment callback adds no TypeScript host API; the current native Plan-pause receipts described above are shared record additions.
