# Bounded Go consumer paths

The Go APIs below share canonical context preparation, policy resolution and admission. They add no checkpoint or event fields; checkpoint v2, event v1 and historical RunReport v1 remain unchanged. They do not certify a mounted Desk integration.

## One-generation observation

`eino.Observe(ctx, run, adapter.ObservationOptions{Tools: declarations})` offers detached schema-only declarations and returns `adapter.ObservationResult`: text, typed tool calls, shared completion usage, the acknowledged checkpoint and its storage receipt. Declarations contain no execution callback. Observation never invokes returned calls, synthesizes a finish request, retries, fails over, or resumes an uncertain observation. A reused durable ID refuses. Ordinary `eino.Run` retains its final-request tool closure, including cap1.

A fresh actual RunStore is required; the legacy single-writer callback profile, resumed executions, approval continuations, executable registries, child registries and native agent loops refuse. At most16 declarations and16 returned calls are admitted; each call has an offered name, unique bounded ID, JSON-object arguments of at most16KiB. Text is at most64KiB and the complete returned observation at most256KiB. Invalid, truncated, unoffered or oversized outcomes return an error, not a successful partial observation. Existing canonical completion records expose reported usage for later usage-budget work; this is not complete usage-budget support.

`Run.RequestOutputCeiling` is an optional positive per-request maximum;0 preserves ordinary bytes. A ceiling of1 leaves resolved model/context output policy and its reserve unchanged. OpenAI-compatible, Anthropic and Gemini encoding pins the actual output field after tier merging and after a supported fallback rewrite. Conflicting OpenAI token fields are also bounded. Unknown protocols and opaque native routes cannot prove this control and refuse. Observation bypasses the provider retry wrapper entirely. Its injected relay capability must map each invocation to one physical generation; an internally retrying host capability cannot be independently constrained by Agent and must not claim support. No raw credentials cross this API.

The existing owner/run identity, request key, selected model/connection revision/profile, durable claim, live authorization and storage receipt remain authoritative. A receipt records a past acknowledged write and grants no new dispatch authority. Cancellation, changed currentness and lost storage acknowledgments do not replay an observation. A retained unknown result remains uncertain.

## Protected opening projection

Set `Run.OpeningProjection` to `runcontext.OpeningProjection{PreviewPaths, Project}`. The trusted host declares exact JSON-pointer paths to source-preview **string leaves** in its complete structured opening. All undeclared values are protected. The callback receives a detached raw input and bounded canonical `Fit` feedback; it returns only replacements for declared paths. Each replacement must be a prefix of the original preview. Duplicate JSON members, duplicate/overlapping paths, ancestor replacement, absent/non-string leaves, additions and changed preview content refuse. The host is responsible for declaring only source-preview leaves; Agent does not infer semantic authority from JSON field names.

The callback runs after actual instructions and the final offered schemas are known and before generic previewing. Each admitted adapter session calls the trusted host projection once; managed retries reuse detached replacements and recheck the current canonical allowance. Fit includes full JSON/message framing and output reserve, allows at most32 probes, and expires when the callback returns. Protected content that cannot fit produces typed context refusal before a physical call. Both adapters retain the complete projected opening; the final encoded request has another canonical input-budget check. Without a configured hook, generic chat preview/retrieval behavior is unchanged. The hook is trusted host code, not an enforced no-I/O sandbox.

## Native termination and pre-admission disposition

The standard `project` / `agent project` certification still requires canonical callback refusal and continuation. Separately select `project native termination` or `agent project native termination` to test an actual native binding which ends an unoffered protocol invocation before its executable canonical callback. It is opt-in and absent from default standard coverage. Missing capabilities, canonical clean continuation, fabricated errors and missing release proof fail the selected claim.

`AgentCallbacks.NativeTermination` is a live harness capability. The bound host reports the exact unoffered call using its invocation token and returns the resulting error. The harness binds proof to the actual request digest/offer, observes actual callbacks and accepts only that live error after invocation release is acknowledged. Wrong, duplicate, mismatched and late receipts refuse. The earlier offered read may execute; the unoffered invocation must have zero callback/execution, fail the invocation and gain no durable executable claim. This capability grants no tool or continuation authority. Package disposable stand-ins prove harness behavior; only the downstream owner can prove its actual private account/process release and bridge behavior.

`ProviderRelease.NotAdmitted(invocation)` is a distinct live pre-admission disposition for an exact typed agent `not-started` return with zero callbacks. `ProviderDispositionAttempt` distinguishes `not-admitted`, `released` and `unknown`; the compatibility `ProviderReleaseAttempt` accepts release only. Duplicate, mixed, wrong, late or untyped/started evidence refuses. The delegation coordinator accepts a valid never-admitted busy child without pretending to release another owner; started or uncertain children still require actual release. The existing durable dispatch row retains its uncertainty state and typed not-started failure separately. No historical release is manufactured and completed child records are not redispatched on restore.
