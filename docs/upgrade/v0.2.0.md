# v0.2.0

Upgrade from v0.1.0. This guide backfills the host work explicitly recorded in
that release's notes; it does not establish compatibility for unlisted inputs.

## Host changes

Supply one `ChatContext` per chat through `context.chat` and dispose it when the
chat ends. Supply Runtime identity/version for immutable read-cache keys. Set
`context.memory: false` when memory is disabled; otherwise the reserve remains.
Implement the then-current recall rule: the first user turn's first text part up
to `STATE_HEADER`. This rule is retired in v0.4.0.

Provide the connection per run and `modelsFor({connection, engine, family, model})`
returning optional critic/child models and concurrency. Replace assumptions that
`childModel`/`concurrentRequests` are capability-record members with this host
seam. Set `adversarialReview` where the host previously invoked the critic.

Display delegated task reports, open questions, partial results and figures;
route `message_progress` by task id. Preserve task ids for resume, references and
shared chat context. Retry reuses eligible results unless `delegationReuse: false`.

## Records and refusals

Carry the new delegation/batch figures and context through checkpoints. Respect
the critic allow-list, profile ceilings, shared allowance/reserve and unoffered
agent-call refusals. The release notes do not specify a general record-version or
downgrade migration; validate retained records with the target release's schemas.

Based on the [release notes](../releases/v0.2.0.md) and [tagged source](https://github.com/Judgment-Pack/judgment-pack-agent/tree/v0.2.0). These guides were backfilled later; their presence does not alter historical release artifacts.
