# v0.9.0

Upgrade from v0.8.1. Preserve reasoning omission and supply discovery evidence
only for the selected model before admission.

## Input and request migration

An omitted native author preference now leaves provider reasoning absent. Table
defaults remain when supported; otherwise use discovery's default or omission.
Explicit unsupported chat/project preferences refuse rather than silently change.
Without discovery the documented prior child/sub-agent defaults remain admitted.
Do not copy raw effort/thinking back into a resolved request or delegated child.
Custom request builders must use the resolved session boundary; carry the child's
actual discovery evidence and selected role binding through fresh admission.

Native Node.js 22+ ESM is now supported as well as bundlers. Keep the package's
emitted module paths/JSON attributes intact; `testing/captureGlobal` is additive.

## Record upgrade and downgrade

Resolved policy members/events/checkpoints may carry `source` (`layer`,
`model-default`, `discovered`). v0.9.0 reads v0.8.1 members without source as
layer-supplied. Upgrade readers first. Do not give v0.9.0 checkpoints to v0.8.1:
its closed Go decoder rejects source-bearing members, although its TypeScript
checkpoint reader accepts them. Inconsistent saved delegated bindings now refuse;
repair host configuration through supported admission rather than rewriting records.

## Consumer dependencies

Refresh and audit the consuming application's own graph; the library's MCP SDK
pin and repository lock do not repair an existing consumer lock. SDK server
protections need explicit host configuration. Review the release notes' bounded
braces deferral (#161), which is not remediation or permission for host-owned
filesystem tools/changed imports to use vulnerable paths.
