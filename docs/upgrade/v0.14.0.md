# v0.14.0

Host upgrade guide from v0.13.2. Apply earlier upgrade guides first. Complete the release
prerequisites in the [release notes](../releases/v0.14.0.md) before pinning a published
artifact. No record format changes version in this release, so a host that uses none of its new
features writes the record versions v0.13.2 wrote. It sees v0.13.2's bytes, apart from the changes
this guide states for every host (each section names its own), among them the approval block's last
member `decidedAt` (#309), the redacted form a durable run records of a call's result (#343), of a
Runtime read and of a failure's detail (#352), and the bounds on what a tool source's schemas keep
as written (#308).

## An approved response on the agent wire (#309, #317)

These rows answer the "Not in this release" rows of the [v0.13.2 guide](v0.13.2.md).

| Change | Host action |
| --- | --- |
| On the durable agent wire, the request after the person's decision carries the approved call's result in the continuation's data block. Before this release, the paused invocation's recorded request was sent again, and the model was not told the result. The block's data now ends with `decidedAt`, when the decision was taken, on every engine. A takeover after the approval is answered carries the block again. (#309) | A host that reads the block's data accepts a last member `decidedAt`. Nothing else. |
| Under task steps, standalone and through the coordinator, the approved continuation goes on to the end. Before this release it sent the recorded request again and stopped `stopped`, with "no usable complete response". (#309) | Nothing. |
| After an answered approval and then a Plan pause, the Plan decision goes on, standalone and through the coordinator. Before this release it failed `HostOutcomeUnknown`, because the approval pause's invocation stayed `unknown`. (#309, #312) | Nothing for a run started on this release. A run that already failed so on v0.13.2 was not tested here; start a new run for its work. |
| A Plan decision whose continuation delegates goes on, through a takeover after the batch too. A later parent open is not given a Plan decision that the checkpoint shows taken. (#317) | Nothing for a run started on this release. |
| A recovered agent invocation whose outcome is `unknown` is sent again as recorded only where it carries the response's newest continuation: the decided approval's block, or the handoff's answer. One that does not (it ended at the approval pause, or at a handoff the response has gone on from) now gets a fresh request instead of a re-send, under task steps as well. An invocation lost after it was sent still carries the newest continuation: it is sent again as recorded, and under task steps it is refused `HostOutcomeUnknown`, as before. (#309, #317) | Nothing. Expect a fresh request, not a re-send, on that path. |
| In Go, a native Plan decision stored its checkpoint in a spelling that is not canonical text. On a store that keeps the run's history, that history reads a checkpoint only as canonical text, so any later open of such a run is refused `HistoryInputInvalid`. That was already so on v0.13.2. The writer now stores canonical text. A run whose Plan decision was stored by v0.13.2 stays refused; there is no migration. (#317) | Start a new run for the work of a run whose Plan decision was taken on v0.13.2 in Go. |

## Source schemas past the bounds on the words they keep (#308)

| Change | Host action |
| --- | --- |
| A source whose offered schemas keep more words as written (enum members, const values, names, `required` entries, `$ref` pointers) than the bounds allow is made a catalogue whatever the schema budget: more than 64 members in one `enum`, more than 64 names in one `properties`, `$defs` or `definitions` map or one `required` list, or more than 4,096 UTF-8 bytes of those words across the source's tools. Its tools are catalogue entries, and the model reads a schema only in `load_tool`'s answer, framed as data. Such a source is out of the budget's count and bytes, so a source the budget made a catalogue before may now be offered with its schemas. A bound-catalogued source is held to `cataloguedTools` (default 64) and `catalogueBytes` (default 24,000), and its tools past them are withheld with a guardrail. (#308) | Expect such a source's tools to be called after `load_tool`. Keep a source's schemas within the bounds where its tools should be offered with them. |
| An `enum` or `const` holding a lone surrogate is dropped with a guardrail, as one holding a string over 64 bytes or a line break already was. The guardrail's detail now reads "holds a string over 64 bytes, a line break or a lone surrogate, or is no list, and it is not offered". (#308) | A host that matches that detail's text reads the new wording. |
| A call missing a member its schema requires is refused with "a member the schema requires is missing from <where>: entry N of its required list, counting from 0", which names the entry by its place in the list, never by its text. Before this release the refusal named the member ("… is required and missing"). (#308) | A host that matches that refusal's text reads the new form. |

## Redacted durable results (#343)

| Change | Host action |
| --- | --- |
| In a durable run under redaction on store, a host or Runtime call's result that the record guard changes is committed in the form the guard leaves, and the call is answered with that same form: the `tool_result` text, `approval.result` and the stored row carry its `[redacted: …]` labels. Before this release such a run ended `StorageOutcomeUnknown`. A result the guard leaves unchanged is passed through as before. A guard refusal (refuse mode) or an unacknowledged commit still ends `StorageOutcomeUnknown`, and nothing runs again on resume. A job's start or cancel is answered from its job record, as before. No event shape, schema or outcome code changes. (#343) | Nothing. Expect `[redacted: …]` labels where such a run used to fail. |
| An external read is answered with the copy the receipt admission checked, in the form the guard leaves of it. (#343) | Nothing. |
| A durable handoff's parent is given the continuation its record holds (`handoff.continuation`), which is what a resumed run gets. (#343) | Nothing. |

## An ask is saved before it is shown (#342, #349)

| Change | Host action |
| --- | --- |
| On a durable run, a custom source's ask for approval is saved paused before the adapter shows it or stops the provider. If the save fails, the approval is withdrawn and the run ends with the storage failure, `unknown`/`storage`/`unknown` in both languages: nothing is shown and the call is not run. In Go the ask is saved under the invocation's context, so a provider's per-call context that ends once the ask is made no longer withdraws it. (#342) | Nothing. |
| In Go, a host's error is read as the package's own pause only where the run claimed a wait or a handoff, the pause stopped the invocation's context, the caller's context is still live, and the error is a cancellation, the context's error or the Tool error itself. A caller's own cancellation, a host stop that closed dispatch before the save, and a storage failure end as before. (#342) | Nothing. A provider that answers the pause with its context's error needs no change. |
| A Runtime action's ask whose save was refused, or whose acknowledgement was lost, ends the run with the storage failure, `unknown`/`storage`/`unknown`, on every engine: nothing is shown and the Runtime is not called. Before this release the TypeScript codex run ended with no error and its checkpoint `complete`, vercel reported `storage`/`not-started` and deepagents `unknown`/`model`/`unknown`. (#342, #349) | A host that routes on a failure's code reads `unknown`/`storage`/`unknown` there. |

## Goal commands carry a worker's fence (#315)

A host-facing change to the goal commands and the store's goal port. Nothing changes for a host that sends every goal command through
the store itself.

| Change | Host action |
| --- | --- |
| A goal command sent through a worker's fenced view (`fencedRunStore`, `unattendedRunStore`; Go `FencedRunStore`, `UnattendedRunStore`) presents that view's fence in the store's transition, `run-goal.json`'s new `fence` member. The store decides it only while the fence is current for the command's run. A displaced worker's `create`, `pause`, `abandon` or any other command is refused `LeaseRefused` by the lease's own reason (`stale-epoch` after a takeover), and a fence of another run `resource-mismatch`, with nothing journaled, seized, sent or changed. Before this release a stale view's command was decided as the host's. | A host store kind: in `commandGoal`, check `transition.fence` against the store's own leases in the command's transaction, before the record is read for a repeat, and refuse as the lease refuses, journaling nothing. A store kind built on the package's goal table passes its own lease check to it: TypeScript `new GoalTable(clock, checkFence)`, whose `checkFence(fence)` is synchronous, throws the lease's refusal and returns nothing; Go `NewFencedGoalTable(now, check)`, whose `check(fence)` returns the lease's refusal or nil. Built without one (`new GoalTable(clock)`, Go `NewGoalTable(now)`), the table refuses every fenced command `GoalCapabilityRefused` `store-unsupported`, and so does the TypeScript table where the check answers anything, a promise among them. Then pass `runStoreGoalConformance` (Go `CheckRunStoreGoalConformance`), whose `goal.fence.*` properties hold it. A store that ignores `fence` fails `goal.fence.stale`, and so does one that answers a repeat before it checks the fence, checks it only where the run has a record, compares only its epoch, or refuses with a `GoalRefused` of the lease's reason (#361), and one that takes the same owner's earlier epoch as current (#368). Where it declares `leasePrincipals`, a store that ignores the fence's principals fails `goal.fence.principal` (#368). A host that commands through a worker's view: expect that refusal where the worker was displaced. |
| `abandonGoal` through a worker's view takes the run's lease, so that view is stale afterwards. (#315) | Retry an abandon through the store itself, or through a view of the fence its answer holds. |
| `actor` is a label the host attests. The package and the store check nothing about who sent a command; the fence says only that the view's lease is current. (#315) | Decide who may issue a command in the host, before the call. |
| A goal refusal's record, `{version: 1, reason}`, has the shape of a lease refusal's, and a reason such as `invalid` is both. Unchanged. (#315 L-4) | Route a refusal by the error's name (`GoalRefused`, `LeaseRefused`), never by its record alone. |
| An abandon retried from a new process, after a crash between its sends and their journal, hands `cancel` the same `operation` as the attempt that crashed. The reference effect host forgets its admissions on restart and lets that cancel through again. (#315 L-2) | Make `cancel` idempotent by `operation`, or use an effect host whose admissions outlive its process: then the retry answers `already-admitted` and sends nothing again. The job's record keeps the crashed attempt's request. |
| `abandonGoal` on an achieved or abandoned objective refuses `objective-terminal` and sends nothing. Unchanged. (#315 L-6) | Stop a terminal objective's jobs, such as an achievement's waived ones, with `abandonJobs` under a command of your own. |
| A journaled `failed` delivery lets the next `create` through, although that job was never asked to stop. Unchanged. (#321's review, L-2) | Send it again with `abandonJobs` under a new command before creating the next objective. After the next objective exists, that call asks its jobs too. |
| An abandon whose deliveries can never be journaled, because `abandonJobs` always throws or the store always refuses them, holds every later `create` on the run at `abandon-unfinished`. Unchanged. (#321's review, L-1) | Start a new run for the work. |
| A required step the model marks `not-needed` ends the objective's legs (only `pending` and `in_progress` count as left), and `achieve` still requires every required step `completed`. Unchanged. (#330's review, LOW-4) | Expect such an objective to be abandoned, not achieved. |

## The record guard over reads without a dispatch row (#352)

| Change | Host action |
| --- | --- |
| In a durable run under redaction on store, a Runtime read through `callTool` (for example `get_schema`) is answered, shown in its `tool_result` event, kept in the chat and cached in the form the record guard leaves of it. Before this release a native agent got the Runtime's text unchanged, and on the API engines the next model request could not be recorded (`ContinuationNotRecoverable`). (#352) | Nothing. A run that records nothing is answered as before, except that a read a durable run kept in the chat's cache is served to it in the recorded form. |
| A durable run is served an entry of the chat's read cache only where the record guard leaves it unchanged. If the guard would change it (for example an entry a run that records nothing kept, or one from a stored chat), the read runs again and its recorded form replaces the entry in the cache. If the guard refuses it, the call fails with the guard's refusal, and nothing runs. (#352) | Expect one more Runtime call where a stored chat's cached read holds text the guard redacts. |
| In a durable run, a chat entry read by id (`read_window`, `read_context`, a search of one item, an image), and one its restored checkpoint referenced, is read in the form the record guard leaves of it, and the run's checkpoint carries that form. The chat keeps its own entry. Before this release the checkpoint stored the entry as the chat kept it. If the guard refuses the entry, the read fails with the guard's refusal, and a resume whose checkpoint references such an entry fails to start with it. A durable run's search of every item, or of the attachments, matches each chat entry in that same form, without making it the run's; before this release it matched the chat's own text, so a search could find, and place, text a read of the item no longer showed. A refusal of any entry fails the search. (#352) | Nothing. |
| In a durable run, a call's or a model's failure is stored with the form the record guard leaves of its `detail`, read whole (as far as 16384 UTF-16 code units past the cut, and on every use of the same error) and then cut to 1000 UTF-16 code units. A host or Runtime call fails with that same form, so its record and what the model is given of it agree. A model's failure is only stored in that form: the model call still fails with its own error. Before this release the detail was stored and delivered as written, and an authored detail was cut before anything read it, so a match the cut split (a private key whose END marker lay past unit 1000) was not found. A match that ends past the margin, such as a private key whose END marker does, is still not found, and the detail is stored as cut. If the guard refuses the detail, the call ends as `StorageOutcomeUnknown`. (#352, #367) | Nothing. In TypeScript the `AIFailureError` a tool threw is given the redacted form in place, its message too: a host that keeps that error object sees the change. `authoredFailure` now cuts a detail as Go's `failure.Authored` does: a surrogate pair at the cut is left out whole. |
| A durable handoff's `answer` is stored in the form the record guard leaves of it, as its `continuation` already was (#343). (#352) | Nothing. |

## A successor's store declares what it lacks (#362)

Successors (#340) are new in this release, so no released host made one.

| Change | Host action |
| --- | --- |
| A successor's create reads the lease port, the wait export (`exportWaits`) and the deadline reader (`readRunDeadline`; Go `RunDeadlineReader`) of the store value it is opened through, and every later open the wait export and the deadline reader. A store value without one of them is refused `SuccessorRefused` `invalid`, with nothing written, unless it has no lease method and declares itself unleased. A wrapper that exposes fewer of the store's ports is refused, where it was read as a store that holds no leases, waits or deadlines. (#362) | A store kind with no lease port declares `unleased: true` (Go: a method `Unleased() bool` answering true). The declaration is the host's attestation, which the package cannot check: declare it only of a store that holds no leases, never of a wrapper that hides a leased store's lease methods. A store kind with the lease port and no waits answers `exportWaits` with no waits and `readRunDeadline` with none. The wait conformance kit holds a store's `readRunDeadline` to the deadline it holds, across a restart (`wait.deadline.read`, #368). A host that wraps its store passes every port through, or opens successors through the store itself. The memory stores need nothing. |
