# v0.8.0

Upgrade from v0.7.0. Integrate the newly declared policy, model/provider,
sub-agent, memory, edit and record seams before enabling their features.

## Host inputs and lifecycle

Supply policy as run/project/table layers and expose each resolved choice's
provenance. Declare provider capabilities, fallback connections and sub-agent
profiles/budgets; keep children within the parent's reserved budget and frame
results as data. Approve memory proposals as writes; preserve the old draft when
a proposal edit is refused. Supply compaction only through its bounded framed
summary path, retaining replaced-turn digests.

Implement retention/deletion and record export in the host. Apply the package's
store/output guards to the declared model-derived record members. Declare and pin
person/service identity on each source; show identity in reports and ask the first
service act. Carry failover state, per-provider/model usage and pending steering
across checkpoints. Price usage in the host without inventing missing tokens.
Record corpus entries only after redaction and replay them using recorded transports.

## New refusals and records

Handle policy admission, invalid sub-agent/memory/edit/compaction inputs, output
or store redaction failure, expired records, changed/credential-bearing identity,
exhausted failover and out-of-bounds steering as refused operations. Correct the
input/declaration or obtain fresh authorization; a fallback is not authority to
cross an undeclared provider or identity boundary. Adopt the release schemas for
new checkpoint/report members. The historical notes do not enumerate a numeric
record-version migration or promise old readers can consume the new records.
