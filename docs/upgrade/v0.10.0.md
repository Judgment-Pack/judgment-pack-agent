# v0.10.0

Candidate upgrade from v0.9.1. This guide does not assert that v0.10.0 has been
released. Apply the v0.9.1 retired-input migrations first when upgrading from older
versions, then make the following host changes before pinning this candidate.

## Record versions and readers (ADR-0024)

Upgrade readers before writing checkpoint version 2 and event/policy version 1.
Readers also accept checkpoint 1 and historical unversioned event/policy layers;
newer versions and unknown structural members refuse by name before interpretation.
Preserve declared arbitrary payloads. Historical reads/exports retain supplied
version and lifecycle metadata; resumed checkpoints write version 2 without
extending retention. Downgrading a host does not make newer stored records readable.
Do not edit retained records to hide an unsupported version/member.

## Storage, durable handoff and source APIs

TypeScript `ChatStore` operations become asynchronous and plan updates use revision
comparisons: await them and honor conflicts. New plan references require opaque
artifact/dialect ids and content digests. Migrate legacy file locators through an
explicit host resolver; the package does not infer filesystem/URL authority.
Go supplies plan/reference helpers and has no ChatStore.

For optional `RunStore`, implement atomic checkpoint/event commits, opaque
revisions and run-scoped cursors; validate the backend against conformance. One
root writer serializes parent/child transactions; dispatch/dependent work waits
for acknowledgement. Conflicts and uncertain outcomes stop dispatch. Provider
managed durable handoff requires live provider-release acknowledgement from the
host bridge; local socket close is insufficient. Explicit RunStore model calls
buffer at most 4 MiB until completion and acknowledgement, delaying progress.
Existing checkpoint callbacks cannot import a full RunStore journal or promise
physical persistence/exact recovery. Preserve version-2 `valueJSON` companions for
retained JSON order/digests; duplicated text still counts toward 4 MiB. Corrupt
historical evidence remains refused. Authorization, leases, secrets and backend
selection remain the host's; no Desk backend is installed.

## Task plans, tool names and approval events

Use package-issued execution-scoped step ids. Carry an id to retain a step;
omission creates a new one. `update_plan` cannot create completion or rewrite a
terminal step. Rename any conflicting host `complete_plan_step` tool. Complete an
active step with that action, the exact revision and acknowledged same-run scoped
evidence, or a not-needed outcome with a reason. Callback-only hosts lack the
observation owner for evidence-backed completion; show historical completion as
unverified. Preserve terminal rows, accepted snapshots, references and pending
drift decisions on resume. Changed pins, stale evidence/revisions and invalid
completion refuse; revise or collect valid evidence through the supported APIs.

Dispatch approval UI by `approval_requested.purpose`: `plan-drift` is a plan
candidate decision, not tool-call approval. Go `Name`, `Tool`, `Source` are optional;
check purpose/presence before dereferencing. Submit the exact pending plan decision;
it grants no tool/source/argument authority and leaves the current plan unchanged
until admitted. Default plan-removal departures pause for human approval.

## Proposal input and numeric admission

Native `propose_pack` now requires full proposal text in `documentJson`. Retired
`document` refuses: update native tool offers to the exported schema. Fenced
proposals retain their envelope. Numbers whose mathematical decimal value changes
under canonical serialization refuse (for example 9007199254740993); equivalent
decimal/exponent spellings and negative zero may normalize. Edits, undo and resumed
proposal text use the same predicate. Correct the original proposal rather than
resending rounded values. Numeric-loss/source-work-bound refusals stop automatic
reformat; malformed JSON retains its reformat request. Already-rounded historical
text cannot prove original precision; arbitrary-precision acceptance is not added.

## Gateway pins and reports

For Gateway registrations, supply complete approved canonical descriptor-snapshot
bytes and current observations under that metadata. A changed capture timestamp
requires newly approved registration. Changed/malformed/failed observations refuse
before execution, including approved continuation, and stay latched across tools,
children and overlapping observations. Digest-only registration remains an explicit
legacy mode. Do not rewrite historical records or infer independent verification
of the host observer.

Use the version-1 canonical run report over terminal checkpoint facts. It excludes
internal request/context/journal payloads and does not infer missing usage/totals.
Optional bounded event pages corroborate the checkpoint/cursor; they do not prove a
complete or authentic prefix. Evidence reports provenance rather than independently
judging task fulfillment.

## Toolchain, advisories and release evidence

Raise Go consumers from 1.25.0 to **1.26.0 or newer**; repository/CI remains 1.26.10.
Review the release notes' linked Go assessment before changing build configuration.
The recorded OpenPGP/PDF #192 exception expires **2026-11-07 00:00 UTC** and applies
only to v0.10.0 / go/v0.10.0, native Linux/amd64, CGO enabled, default tags and
Go 1.26.10. Vulnerable packages remain in the graph; only their absence from that
build's package/test closure was assessed. Other configurations are unverified.
The exception is a bounded reachability decision, not remediation.

Live answer quality was not evaluated for this candidate. The maintainer deferred
the baseline/candidate comparison to the Desk lane; #169 remains open with Desk
acceptance/scheduling pending. No completed replay token total or attributable
monetary cost is available. Offline differential/replay tests and CLI feasibility
are not live quality evidence; all other release checks/reviews still apply.
