# v0.6.0

Upgrade from v0.5.0. Skills are optional host declarations; the existing
approval lifecycle remains the host binding.

## Host and record changes

Declare skills with name, version, source, instructions, referenced declared tools
and approved digest. Expose the catalogue/load/unload lifecycle and show loaded
skills and source counts. Re-approve changed digests; a skill grants no tool or
approval authority. Children receive no catalogue.

Preserve `checkpoint.skills` and source figures across resume; withdrawn or
changed skills are not silently restored. Preserve the framing marker saved with
a pending approval so the continued tool prefix remains byte-identical. Restoring
a v0.4.0 agent-unit checkpoint drops the old batches' invented `modelRequests: 0`.

## Refusals and compatibility scope

Invalid, unpinned, changed or oversized skill declarations are withheld with a
guardrail. Migrate declarations and obtain re-approval rather than changing
checkpoint rows. The notes do not identify a newly required input for hosts that
do not declare skills, or a general downgrade promise; consult the release's
schemas before passing its records to older readers.

## Evidence and adoption

Based on the [release notes](../releases/v0.6.0.md) and [tagged source](https://github.com/Judgment-Pack/judgment-pack-agent/tree/v0.6.0). These guides were backfilled later; their presence does not alter historical release artifacts.
