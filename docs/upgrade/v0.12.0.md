# v0.12.0

Host upgrade guide from v0.11.0. Apply earlier upgrade guides first. Complete the release
prerequisites in the [release notes](../releases/v0.12.0.md) before pinning a published
artifact. Checkpoint and run event formats are unchanged in this release.

## Record formats

| Record | Change | Host action |
| --- | --- | --- |
| Dialect draft checkpoint and review proposal (`dialect-draft.json`) | Written as version 2, carrying `researchIndex` (the top index) and never `researchDeclarations`. Version-1 records written by v0.11.0 still read. The schema refuses a version-2 record with `researchDeclarations` or without `researchIndex`, and a version-1 record with `researchIndex`; only the schema refuses these mixed shapes. Re-encoding a version-1 record through Go adds `researchIndex: null`. | Keep stored version-1 bytes as they are. Do not re-encode a stored version-1 record through Go and store the result as the original. |
| Dialect authoring ports (`dialect-authoring.json`) | `read.cursor` is new; the port shapes `fieldIndexRequest`, `fieldIndexPage`, `pageRequest` and `page` are new. | Implement the two paged read-port members below. |
| Run lease (`run-lease.json`, version 1) | New: the lease, the fence `{resource, owner, epoch}`, the effect admission, and the refusal and capability-refusal records. The epoch is a canonical base-10 string from `1` to `999999999999999999`, never a JSON number. | Store the epoch exactly (a SQL `bigint` holds it). A fenced run's checkpoints and events have the same shape and versions as an unfenced run's. |
| Tool taxonomy (`tool-taxonomy.json`) | `checkKind` gains `rehearse`; `check/rehearse` requires effect `pure` or `read`. | None unless the host declares rehearsal tools (below). |

## Dialect authoring: the inventory by digest (#243, #252)

The read snapshot no longer carries the original declarations inline.

- **Go.** `DialectSnapshot.ResearchDeclarations` is removed. Supply `ResearchIndex`, the top
  index (`DialectResearchIndexOf(revisions)` computes it from a complete inventory), and
  implement `DialectAuthoringPorts.ReadFieldIndex(ctx, request)` and
  `ReadDeclarations(ctx, request)`. A Go host decoding a JSON snapshot that still has
  `researchDeclarations` silently drops the member, so the snapshot reads as having no index:
  migrate the producer explicitly rather than relying on decoding. `DialectIndexRevision.Fields`
  is `*int` with `Digest` and `Bytes`. `ReadDialectDeclarations` takes the field index reader
  first.
- **TypeScript.** Supply `researchIndex` (`dialectResearchIndex(revisions)`) and implement
  `readFieldIndex(request, signal)` and `readDeclarations(request, signal)` on the read port.
  A snapshot that still carries `researchDeclarations` is refused by name.
- **Pages.** A field index request names `id`, `packKey`, the collection `revision`,
  `inventoryDigest` and `entry`; a declaration request names the same binding with `cursor`
  and `limit` (at most 1,000). Each page echoes its request and stays within 1 MiB of
  canonical JSON. Every page is checked against its digest before use; see
  [paging original declarations](../design/dialect-authoring.md) for the full refusal list.
- **The bound and the host's obligation.** The top index fits every collection of at most
  1,000 records with at most 30 fields and field names of at most 64 bytes. Build the
  inventory from each record's original revision, not from the whole recipe history: an
  inventory of more than 1,000 revisions is refused.
- **Model surface.** `read_dialect` shows a `researchInventory` summary and gains an optional
  `cursor`; with it, it returns one checked page and `nextCursor`. `propose_dialect` is
  unchanged.
- **Consumers.** Preview and review code that needs declarations reads them with
  `readDialectDeclarations` / `ReadDialectDeclarations`, which apply the same checks.

## Receipt quarantine (#242)

A source result is not reusable context, not Plan step evidence and not reachable by any reader
until its receipt verifies. A rejected, missing, oversized or expired receipt, or an error
result, is recorded once as the call's uncertain outcome: the `tool_result` event, the durable
dispatch row in state `unknown`, and, in the API adapters, the operation listed as failed. Its
bytes are retained nowhere. The physical call is not retried and its source-call accounting
stays consumed.

- A Gateway receipt whose unsigned `salts` carry a member other than `args` and `statement` is
  refused. Check that the Gateway the host pins writes no other member.
- TypeScript keeps a verified custom-source receipt in the retained value; Go does not. This is
  a declared parity difference; do not rely on the retained receipt across languages.
- New TypeScript exports: `ReceiptAdmission`, `receiptAdmission` and `RECEIPT_WITHHELD`.
  `RunWriter.invoke` gains an optional last parameter.

## Run leases and effect-host fencing (#223, #253)

Leases are opt-in. With no lease configured nothing changes.

- **Store kinds.** A store kind that supports leases implements the `LeaseStore` port and the
  fenced commits (`commitFenced`, and with history `commitHistoryFenced` and
  `commitContextSnapshotFenced`), and declares `leaseLifetime` `durable` or `process`. Run
  `runStoreLeaseConformance` / `CheckRunStoreLeaseConformance` against it. The kit certifies
  the port; the host must prove that the epoch survives the store's own restarts and backups.
- **In-memory kinds.** `MemoryRunStore` and `MemoryChatStore` keep leases per process and are
  refused for unattended admission (`store-lifetime`).
- **Effect hosts.** Under a fenced run, every non-read host or runtime act goes through the
  effect host with the fence and an idempotency key. Use `ReferenceEffectHost` (Go
  `NewReferenceEffectHost`) or certify the host with `certifyEffectHost` /
  `CertifyEffectHost`, which binds certification to the exact instance it checked. A copy, a
  subclass or an embedding type is not evidence.
- **Unattended admission.** `admitUnattended` / `AdmitUnattended` require a store that declares
  lease support with durable lifetime and the reference host or a certified host enforcing
  against that same store. Otherwise they refuse with `store-unsupported`, `store-lifetime` or
  `effect-host-unfenced`.
- **Limits.** Metadata writes (feedback, capture) are not fenced. Certification assumes
  non-adversarial host code; #258 tracks further hardening. An effect admitted before the lease
  was lost is not undone; a takeover refuses an unacknowledged claim as `HostOutcomeUnknown`
  and never replays it.

The host-facing contract is [run leases and fencing](../design/storage.md).

## Rehearsal tools (#241)

Hosts that declare rehearsal tools declare `taxonomy` `check/rehearse` with effect `pure` or
`read`, and begin the tool's own declared description with the words "Rehearsal,
non-binding", followed by the end, whitespace, or one of `.,;:!?)`. Host admission refuses
any other rehearse declaration before provider work. Other paths that take host tools
directly (in Go, the gate's `Open`, `SetOffer` and `EnrollContext`, and eino's `Observe`)
check the taxonomy only.

## Adoption checklist

1. Confirm the release prerequisites in the [release notes](../releases/v0.12.0.md) are
   recorded before pinning the published artifact.
2. Migrate the dialect snapshot producer and implement both paged read-port members in each
   language the host uses; test historical version-1 checkpoints against the released artifact.
3. Keep unattended admission disabled until the store kind passes the lease kit, its epoch
   durability is proven, and the effect host is the reference host or certified.
4. Verify the release tarball and checksums against their attestations and pin the matching Go
   module version `go/v0.12.0` and `go.sum`.
