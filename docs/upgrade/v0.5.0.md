# v0.5.0

Upgrade from v0.4.0. Replace the in-call approval reader with the run-level
approval policy and pause/continue lifecycle (ADR-0008).

## Approval API migration

Return `allow`, `refuse` or `ask` from the host policy. On `approval_requested`,
show the exact call name, source and arguments plus a note field; retain the
paused checkpoint and end the run without keeping an invocation/account open.
Continue the restored checkpoint with `approvalDecision` (call id, decision and
optional note). Go approved continuation requires `Input.Checkpoint`.

Acknowledge `approved` before execution and `executed` with the result after it.
An approved checkpoint without a recorded result resumes as unknown outcome;
never infer permission to run the operation again. Bind decisions to call id and
arguments, including repeated calls of the same tool.

## Record and refusal migration

Read checkpoint `approval` and paused status. Delegation `modelRequests` is now
optional on agent-capability figures (a Go pointer); omit invented zero totals
and sum only figures that carry model requests. The notes explicitly state a
v0.4.0 checkpoint still reads.

Only one approval can wait. Children, Plan, critic and reformat phases refuse act
calls rather than pausing. Treat `approval stale` separately from policy/person
`approval refused`; obtain a fresh valid decision instead of reusing one for a
changed call. Carry the refusal result and note as framed continuation data.
