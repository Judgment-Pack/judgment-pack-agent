# Read-only retained history archives

Archive1 is the retained-history archive wire contract introduced in v0.11.0. It adds `member.source` and defines typed inventory/cardinality and canonical ordering. It does not promise compatibility with earlier unpublished archive prototypes. Released checkpoint, event and report formats are unchanged.

Objects identify unique byte blobs by SHA256 digest; repeated valid roles share one blob. Each mapping and member identifies a typed source with `(source.digest, kind)`. A member carries `source`, exported `digest`/`bytes`, `kind` and `representation`. Mappings and members sort by source digest, then kind; objects sort by exported digest. Duplicate typed keys, conflicting mappings within a role, inconsistent source byte sizes, wrong/missing roles, extra unused blobs and undeclared references refuse. A native checkpoint and a corpus checkpoint chunk may legitimately use identical source bytes.

TypeScript `readDisplay(ref, kind)` and Go `ReadDisplay(ref, kind)` select the expected role explicitly. One-argument lookup succeeds only when the source has exactly one role; ambiguous lookup refuses. Event/query/report/capture readers supply their known roles. Imported archives expose detached display data and canonical archive bytes, with no native object store, execution, tool, resume or admission authority.

Exact mappings preserve original bytes. Redacted views bind original source labels and role to a separately hashed derived wrapper; original labels never claim to hash sanitized strings. Protected scope, dispatch, Plan and reference identities cannot change. Export validates original documents privately and sanitizes whole logical JSON before chunking. Import validates each logical interpretation, compares derived aliases with available original bytes and compares protected identities across interpretations of the same logical payload. A corpus checkpoint must agree with the capture's native checkpoint identity. A self-consistent unsigned archive establishes internal relations, not original execution or provider authenticity; an optional caller pin verifies the expected archive bytes.

The capture reader accepts only exact required native corpus members. Shared handwritten fixtures demonstrate checkpoint/chunk aliases, request/source aliases, repeated empty files, consistent redaction, and refusal of protected identity edits hidden in chunks. Real MemoryRunStore tests export and round-trip shared source/request roles with whole-JSON redaction. Separate original-writer capture and transcript-v1 projection integration now have paired focused application-engine evidence. That evidence uses scripted transports and does not establish live-provider answer quality. Integrated CI, independent review and final release evidence remain release prerequisites.

Typed checkpoint/report/event interpretations also preserve step dependencies and the entire Plan-state task schedule/envelope, including pending candidate state. The lock follows actual typed paths and checkpoint/chunk aliases; similarly named members in unrelated user JSON remain eligible for ordinary redaction. Permitted Plan prose can still be redacted. Task child evidence retains its exact task/checkpoint/result/event/commit identities; its labels do not grant claim authority.
