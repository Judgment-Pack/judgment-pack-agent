# Reading retained corpus captures

`readCapturedCorpus` in TypeScript and `ReadCapturedCorpus` in Go validate an attached capture against a pinned retained journal. `readArchiveCapturedCorpus` / `ReadArchiveCapturedCorpus` apply the same checks to an imported display archive. They return corpus data or the fixed `ReplayUnavailable` result. They never call a provider, execute a tool, resume a run or admit a corpus entry.

The reader requires a complete or stopped native checkpoint, every eligible dispatch's acknowledged capture expectation and exact scoped request evidence, one ordered request row per admission, and all six complete corpus files. Request rows follow journal admission order even when children finish in a different order. Unknown claims, missing or duplicate expectations, conflicting scope/source/request identities, unobserved native callback tools, missing files or malformed corpus material are unavailable. Root-visible events and scoped published tool call/result pairs must agree with the recorded corpus. The original source digest labels never claim to hash sanitized strings.

Capture availability is separate from retained-history completeness. An incomplete or legacy archive remains readable when capture is unavailable. Redacted display objects are not native execution inputs. The native archive capture reader requires exact typed members. Explicit derived view readers consume validated display relationships without treating sanitized bytes as original source bytes. A self-consistent unsigned archive proves no original execution or provider authenticity.

The capture collector core is package-private. It accepts only its original owner and exact live admission tokens; copied tokens, caller markers and checkpoint objects cannot supply acknowledgement. It orders admissions independently of completion, requires a completion acknowledgement for every row, and seals only with its original root token. A child's terminal event cannot finalize a root capture. Publisher enrollment additionally binds the exact original store object privately, once before admissions. Collector bookkeeping never invokes store/provider/tool APIs or grants resume authority.

Original TypeScript and Go writers now enroll capture before admission, attach expectations to the claim transaction, acknowledge observed frames after the terminal result receipt, and finalize through the original root after its terminal event receipt. Handwritten actual-engine tests exercise concurrent children, model responses and native callbacks. Their transports are scripted fixture evidence and do not establish live-provider answer quality or authenticity.

Go's existing callback recorder preserves CapabilityNeeded, ProviderRelease and NativeTermination references and forwards original callback arguments. Its private recording snapshots are detached from later provider mutation. Portable Go corpus manifests use the contract's lowercase files member names.

Whole logical corpus material must be redacted before chunking and publication. The private publisher consumes an enrolled same-store opaque seal into an opaque preparation. It validates original material strictly before redaction, then validates the clean complete corpus, stages immutable chunks privately, and appends existing capture metadata through the original store queue/CAS without changing execution bytes, revisions, events or allowances. The manifest is host recording configuration; live enrollment must supply its original configuration and resolved root policy. Store-commit and external-delivery outcomes remain distinct. A failed or unverifiable acknowledgement returns capture unknown/delivery not-attempted for that invocation and sends no material. A verified capture may report delivery delivered, unknown or not-requested. An explicit retry of the same opaque preparation uses the existing exact idempotency key; there is no automatic storage or execution retry. A sink is attempted at most once per preparation, including after a sink error. Unknown delivery never means that a verified committed capture was absent. Exact receipt row/object hashes are rechecked before exposing delivery material.

Archive1 typed references now distinguish source digest plus role from unique byte blobs; identical checkpoint/chunk bytes can be represented without padding. Known capture reads request their exact roles. See [archive wire contract](history-archive.md) for the unreleased member.source and ordering change. Original application captures and imported native-corpus fixtures use the same strict read-only relationship checks.

Use `readCapturedCorpusView` / `ReadCapturedCorpusView` for retained captures and `readArchiveCapturedCorpusView` / `ReadArchiveCapturedCorpusView` for imported display archives. They return `{checkpoint, entry}`. Both checkpoint positions contain an explicit `CorpusCheckpointView`: version 1, kind `corpus-checkpoint-view`, original source digest/bytes and source version, independently computed derived digest/bytes, representation `exact` or `derived`, and a closed display document. The standalone schema selects the frozen checkpoint 1/2 graphs and current checkpoint 3 graph. `readCorpusCheckpointView` / `ReadCorpusCheckpointView` validate self-consistency only; provenance comes from the complete validated capture/archive relationship.

Exact requires the original byte identity and unchanged native execution reader. A derived Plan display preserves original revision, task dependencies, schedule/envelope, scope, dispatch and source labels even when prose redaction changes its actual digest. It never repairs a native revision. Both the bare sanitized Plan and its wrapper are refused by native execution readers. The publisher's original preflight remains strict before redaction; only its clean preflight uses display validation. Stored RunCapture still pins the original native checkpoint and actual file manifests. Missing or interrupted capture is unavailable.

Fresh Vercel, Codex, Go Eino and Go native adapter tests replay recorded material through application engines with scripted transports/tools, recording exhaustion and newly emitted outcome comparisons. Existing certification fixtures separately exercise imported derived Plan material. Replay transports consume recorded frames without comparing fresh model or agent request bytes; original archive request digest checks provide separate source-identity evidence. Neither fixture route establishes live-provider answer quality or authenticity.

The publisher applies the existing fixed output-pattern work bound to complete logical material before staging. Material that exceeds that budget is unavailable and publishes no objects, capture metadata or sink files. The focused positive privacy fixture covers accepted material and inspects staged bytes and delivered files; it does not establish positive redaction across the 4 MiB chunk boundary. Supporting larger logical inputs requires a separate resource-budget or scanning design.


Original live capture enrolls only the original history writer before physical admission. A private token binds each frame to its exact acknowledged claim commit, observation ordinal, request digest and scope. A frame is acknowledged only after the corresponding terminal result transaction is verified. Children share collection but never own root publication authority. Resuming with uncovered earlier physical requests makes capture unavailable; copied journals and imported displays cannot restore live authority.

New captures declare `eventProjection: "transcript-v1"` in the capture metadata. Their corpus transcript excludes `execution_checkpoint` events, and the existing `end` and `recorded` exclusions still apply. Every remaining root author event must match in full and in order. The separately stored terminal checkpoint remains complete. Every original intermediate checkpoint and event remains in retained history and the exported history archive. An absent marker selects the legacy exact transcript. This projection is replay and display data, never native resume or execution authority.

A native synthetic `agent.run` response may carry `x-jp-native-tool-bindings` in its recorded response headers. Its value is canonical JSON mapping every offered alias to its exact original source tool name, with unique aliases and source names. The original native engine supplies its private route table; descriptions and positional guesses are never used. These are capture metadata, never HTTP transport headers. Model responses cannot supply this binding. Missing alias bindings, partial domains, duplicate names and malformed data make capture unavailable. Imported metadata does not create provenance, admission, acknowledgement, enrollment or execution authority.

The whole derived corpus is redacted before staging or delivery under the existing output-guard work limit. A larger corpus may remain unavailable. Publication uses the original metadata CAS; unknown acknowledgements do not cause automatic retries or sink delivery, and a sink is attempted at most once.

TypeScript recording uses the existing `record: true` and corpus manifest/sink configuration on an original history-capable store. Go hosts opt in with `context.Input.Capture` containing `LiveCaptureConfig{Manifest, Sink}` on that original store. Callback-only stores keep their existing recorder path. These configurations grant no authority to imported records or copied bindings.

The unpublished v0.11 opt-in also retains `capture-request.nativeBindings`, a content-addressed reference to the complete canonical alias/source table. The original native adapter issues an internal exact-request proof from its route allocation before dispatch. The original writer stages that table and acknowledges its reference in the same claim transaction as the capture expectation; a lost claim acknowledgement dispatches nothing. The replay reader resolves the table through the retained history evidence role and compares every alias and source, including unused tools. Response headers, descriptions and callback claims cannot create this evidence. HTTP capture cannot carry it.

Earlier native capture observations without that evidence remain readable as history, but their corpus replay is unavailable. Restart and import cannot fabricate the missing original evidence or restore live collector authority. Archive export includes the referenced evidence explicitly; a derived or mismatched table cannot establish original bindings. These consistency checks assume the retained history root supplied by the host; a wholly fabricated unsigned history is not authenticated execution evidence.

An enrolled original capture assigns correlation IDs to HTTP tool call/result events even for noninteractive sessions. This lets the capture verify each retained result against exactly one call. Sessions without capture retain their existing event shapes.
