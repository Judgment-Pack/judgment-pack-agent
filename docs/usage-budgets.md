# Usage budgets

An optional `ContextInput.usageBudget` (Go `context.Input.UsageBudget`) enables admission through the original durable writer. Supply an explicit `UsageBudgetStore`, exact `scope` identity and, for token limits, a trusted `bounder`. It requires an actual `RunStore`; the legacy single-writer checkpoint callback cannot provide this contract. Without this option, request bytes, checkpoint producers and report version remain unchanged.

A scope has resource ID, scope ID, policy revision and fixed limits. Dimensions are `modelRequests`, `providerInvocations`, `inputTokens` and `outputTokens`, all nonnegative safe integers. A physical HTTP request consumes one model request even when the provider refuses it. A native provider invocation is a separate dimension: its private model loop is opaque, so physical requests and token guarantees are unsupported there. Its physical-request report subtotal is incomplete, rather than a known zero.

The host must declare the exact connection revision for every admitted author, critic, child and fallback binding. Missing revisions refuse before provider dispatch; a model name is not a revision. Supported token-budget protocols are OpenAI compatible, Anthropic and Gemini. The bounder receives final encoded request bytes after tier and fallback rewrites, exact selected binding/model and the effective encoded output maximum. It must return conservative bounds for configured token dimensions. The package verifies exact integers and all conflicting supported output fields; absent bounds or unknown protocols refuse with `UsageBudgetUnsupported`. The callback is trusted host input, not proof of provider internals or an estimate of future usage.

`MemoryUsageBudgetStore` is a host-owned, ephemeral conformance implementation. Share one instance for the resource across all relevant runs and chats, and seed externally committed usage. A fresh unseeded scope starts at known zero; a seeded omitted dimension remains unknown. Reserve atomically includes external usage, every outstanding sibling reservation and the new upper bound. Scope limits/revision cannot change under an existing scope ID. Inputs are detached; reads cannot mutate held authority. Capacity is bounded at64 scopes,4096 reservations and5 settlement operations per reservation; exhaustion refuses without evicting outstanding work.

Each actual attempt reserves separately, acknowledges its journal through the original run writer, then performs live authorization and dispatch. Package-owned retry wrappers use an internal per-attempt operation; they cannot hide a second send beneath an outer reservation. The host relay capability still represents one physical request per call. A host that retries privately must expose those attempts through the canonical boundary or cannot claim this contract. The package does not copy a provider loop or resolve policy/context again.

Reserve returns immutable `{receipt, created}`. Only the original writer's newly acknowledged live ticket can authorize its exact next dispatch. `created:false`, a read receipt, a restored journal or another writer's ticket grants no execution. Lost Reserve acknowledgement, lost run-store acknowledgement and uncertain provider outcomes retain reservations and refuse automatic replay. Reconciliation validates the same retained IDs and scope against the explicitly supplied store; replacing it with an empty store cannot reset consumption. A concurrent child refusal can stop the original writer before an already reserved sibling sends; that capacity remains held. Admission guarantees a bound, not sibling scheduling or progress. Budget and run-store writes are separate ports: a crash between them can conservatively leak allowance. They are not a shared transaction.

Actual model-text or tool callbacks on the exact live native claim can establish providerInvocations:1 even when the model outcome remains unknown. Startup/retry/status signals and error text cannot. The original writer acknowledges the unknown outcome before settling this count; release and handoff authority stay separate. Lost outcome or settlement acknowledgement holds allowance and blocks replay. Unknown journal state may retain already-known actual figures without treating the uncertain budget write as acknowledged.

Settlement records only explicit observed figures within the declared upper bound. Omitted tokens retain their reservation; they never become zero or predicted provider usage. Repeated provider usage snapshots replace earlier explicit members rather than adding overlapping totals. Fractional/unsafe lexical numbers, duplicates and contradictory facts refuse. An authoritative `never-admitted` store settlement is distinct from observed usage; the execution layer does not infer that proof from error prose, promise completion or a receipt. Uncertain native admission keeps its hold. No monetary price or subscription cost is invented.

Feature-bearing checkpoints use version3, and their checkpoint-bearing events use version2. Feature-free producers remain checkpoint2/event1. Published checkpoint2/event1/policy1 and historical report1 graphs remain frozen. Actual checkpoint3 budget reports use the separate closed `RunReportV2` schema with `usageTotals`; ordinary reports remain `RunReport` version1. TypeScript `readRunReport` returns the discriminated `RetainedRunReport` union: narrow `report.version` before accessing version2 fields. Go retains the version-tagged value rather than decoding version2 into the historical Go version1 type.

Each total has `known` and `complete`: it sums attributable observed facts once from the root journal, including child attempts, without adding child rollups again. Reservations and externally seeded project usage are excluded. Missing dimensions mark completeness false, and safe-integer overflow refuses. Report2 is closed; only its declared members, including optional feedback, are admitted. Host durable-store conformance, full integrated CI/review and private Desk integration remain separate acceptance evidence.
