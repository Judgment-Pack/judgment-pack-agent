# v0.10.0 Go compatibility and dependency assessment

Issue #193 raises the shipped root Go module minimum from Go 1.25.0 to **Go 1.26.0**.
Downstream consumers must use Go 1.26.0 or newer. The repository build and CI pin in
`dev.json` remains Go 1.26.10; the language/module minimum is a separate compatibility
contract, not a recommendation to build releases with an unpatched compiler.
The historical ADR-0004 tree and v0.9.1 release assessment retain their original minimum.
The compatibility matrix derives each consumer probe's minimum from its target module.

## Selection and primary evidence

Primary Go vulnerability records and upstream module requirements were queried on
2026-10-24. [x/net 0.60.0](https://proxy.golang.org/golang.org/x/net/@v/v0.60.0.mod)
requires Go 1.26.0 and selects
[x/crypto 0.57.0](https://proxy.golang.org/golang.org/x/crypto/@v/v0.57.0.mod),
x/sys 0.48.0, x/term 0.46.0 and x/text 0.42.0. The resolved graph also selects
x/mod 0.41.0. Existing graph remediation pins, including yaml.v2 2.2.8, are retained.
The exact imported-module control changes only x/sys from 0.47.0 to 0.48.0;
no provider module or import is newly admitted.

These selections clear the five HTTP/2 records
[GO-2026-6603](https://vuln.go.dev/ID/GO-2026-6603.json),
[GO-2026-6610](https://vuln.go.dev/ID/GO-2026-6610.json),
[GO-2026-6611](https://vuln.go.dev/ID/GO-2026-6611.json),
[GO-2026-6612](https://vuln.go.dev/ID/GO-2026-6612.json) and
[GO-2026-6617](https://vuln.go.dev/ID/GO-2026-6617.json), and the two SSH records
[GO-2026-6354](https://vuln.go.dev/ID/GO-2026-6354.json) and
[GO-2026-6355](https://vuln.go.dev/ID/GO-2026-6355.json).
This version assessment does not imply the whole graph is free of advisories.

## Verification scope

On Linux/amd64 with CGO enabled and default tags, the official Go 1.26.0 archive
was verified against the SHA-256 in the official Go download manifest. With automatic
toolchain switching disabled, `go test -count=1 ./...` passed for the root module,
including the Eino adapter and exact-version dependency controls. A separate consumer
module declaring Go 1.26.0 resolved this local module and compiled imports of its
context and Eino adapter packages using that compiler. This is minimum-compiler
compatibility evidence, not an advisory clearance for the old compiler's standard library.

`go mod verify` passed. Downloaded selected-module checksums were recorded, and existing
checksum entries were retained. The x/sys 0.48.0 admission and 0.47.0 refusal cases pass;
a disposable fixture fails the refusal case when the exact-version comparison is removed.
No admission or verdict implementation changed.

A fresh official `govulncheck -json -test ./...` scan on 2026-10-24 used
`govulncheck` v1.9.0 and Go 1.26.10, Linux/amd64, CGO enabled, default tags. Its JSON
contained no findings for the loaded root-module package/test closure. JSON exit status
alone was not treated as proof: finding records were inspected. The primary database
reported its update time as 2026-10-21 00:27:29 UTC. This excludes graph-only modules,
other platforms and custom tags, and does not establish an OpenPGP or PDF remedy.

The final graph assessment queried the OSV API on 2026-10-24 for all 77 versioned
modules from `go list -m -json all`, without a package reachability filter. Every
batch result was present, no pagination token remained, and both returned primary
records were fetched in full. It reported exactly OpenPGP GO-2026-5932 and PDF
GO-2026-5781. The seven HTTP/2 and SSH records were absent for the selected versions;
the separate retained-primary-record comparison also confirms their fixed ranges.
The graph finding result is distinct from the symbol scan's zero findings.

## Scoped maintainer disposition and exclusions

[OpenPGP GO-2026-5932](https://vuln.go.dev/ID/GO-2026-5932.json) and
[PDF GO-2026-5781](https://vuln.go.dev/ID/GO-2026-5781.json) have no fixed versions
in the retained primary evidence and remain open in
[#192](https://github.com/Judgment-Pack/judgment-pack-agent/issues/192).
The maintainer [approved the fresh v0.10.0 proposal](https://github.com/Judgment-Pack/judgment-pack-agent/issues/192#issuecomment-6388704923)
on 2026-10-24, expiring **2026-11-07 00:00 UTC**. Approval accepts deferring
dependency-path replacement; it does not remediate either graph finding or carry
forward the v0.9.1 exception. It covers only v0.10.0 / go/v0.10.0, native
Linux/amd64, CGO enabled, default tags, built with Go 1.26.10.

The [fresh audit record](https://github.com/Judgment-Pack/judgment-pack-agent/issues/192#issuecomment-6388330609)
at `c89def3d82e18ba1bf1a7f2aa6757da68184a214` covers 77 versioned graph modules
and 425 native package/test-closure packages, with no affected-package import.
Both explicit affected-import refusal controls pass, and removing each owning
safeguard makes its assertion fail. Six pinned Python development dependencies
also returned no OSV findings; npm is assessed separately by the live CI audit.
The [identity reassessment](https://github.com/Judgment-Pack/judgment-pack-agent/issues/192#issuecomment-6388681816)
carries this evidence through `c371d3795eedc4829b9c2cc42de30a9184c171aa`: only a
handwritten contract vector and exact Go formatter output changed after the audit;
dependency inputs, imports and executable behavior are unchanged.

Reassess before each release, at expiry, and immediately on dependency, path, input,
upstream-fix or advisory changes under the [dependency policy](dependency-policy.md).
Other platforms, custom tags, CGO-disabled builds and downstream configurations are
unverified. The Go 1.26.0 compatibility probe does not establish compiler security.
All remaining check, independent review and release gates still apply.

The separate `go/spike` module is an exploratory adapter comparison, outside the shipped
root module and its package/test closure; it is unchanged and is not covered by this
assessment. Platform and custom build-tag claims require their own evidence.
