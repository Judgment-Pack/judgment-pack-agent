# v0.9.1 Zod assessment (release gates pending)

[Issue #176](https://github.com/Judgment-Pack/judgment-pack-agent/issues/176) tracks
[GHSA-mrhx-c7xc-m3w5](https://github.com/advisories/GHSA-mrhx-c7xc-m3w5), which lists
Zod versions below 4.6.6 as affected and 4.6.6 as patched. This draft changes the
harness's direct pin and repository lock from 4.4.3 to 4.6.7. Artifact, installation,
focused regression and consumer checks below passed on 2026-10-23. A fresh live audit,
the complete checklist, exact-head CI and independent review remain pending.

## Upstream source and verified artifact

The [4.6.6 notes](https://github.com/colinhacks/zod/releases/tag/v4.6.6) include
[the collection-size correction](https://github.com/colinhacks/zod/commit/a0ebf970f2d752e5f58527cd2942ff48be4f46bd).
It checks leading upper/exact bounds before traversing arrays, sets and maps, including the
compiled path. The [4.6.7 release](https://github.com/colinhacks/zod/releases/tag/v4.6.7)
names source `b500a2ee95134f81d74da7911d7378dd2853d042`;
[the source comparison](https://github.com/colinhacks/zod/compare/a0ebf970f2d752e5f58527cd2942ff48be4f46bd...b500a2ee95134f81d74da7911d7378dd2853d042)
places it three commits after the correction, with no subsequent change to the corrected files.

The 4.6.6 notes describe a compromised Git credential and removed source commits, and state that
those commits were never published to npm. That upstream statement does not replace artifact
verification. The downloaded `zod@4.6.7` tarball's actual SHA-512 matched the published integrity:

```text
sha512-g8W2D2kU6a8untc053fX1uVBKzM7yqAxW/3zwk83+6RyF2+SKOuV+c0wBDhUwzV1PaGapmZH+rmcUzPf+3CGwg==
```

An isolated consumer containing only registry-installed `zod@4.6.7` passed
[npm's supported signature/attestation verification](https://docs.npmjs.com/cli/v11/commands/npm-audit/#audit-signatures)
with npm 10.9.8: one verified registry signature and one verified attestation. The provenance
subject is `pkg:npm/zod@4.6.7`; its SHA-512 equals those actual tarball bytes. It identifies
`https://github.com/colinhacks/zod`, source commit `b500a2ee95134f81d74da7911d7378dd2853d042`,
and `.github/workflows/release.yml` on `refs/heads/main`. The isolated installed lock names the
same integrity. These results verify this artifact and its recorded source identity, not every
upstream operation or every package in a consuming application's graph.

## Consumer resolution and limits

The harness has no direct production Zod import; SDKs and engines consume it through their own
dependency and peer paths. Their current ranges accept 4.6.7 and affected older versions. A
library's exact pin does not replace a consuming application's lock or every shared SDK copy.

The packed-consumer probe preserves fresh-consumer native imports, browser bundle and declaration
coverage (76 supported entrypoints), including the existing native/browser memory-lifecycle
probe. It traces Zod from each actual installed production/peer package location using Node's
package search order and validates the manifest's owner name. It does not assume that an exported
`package.json` names the package root or that a package has a usable root export; MCP SDK exports
a nested format-only manifest and exposes the supported client/server subpaths.

All 13 Zod-consuming locations in the repository and fresh consumer resolved 4.6.7. A separate,
handwritten old-lock fixture fixed the current engine/SDK dependency set with Zod 4.4.3. Installing
the candidate harness tarball into that fixture left 12 of its 13 harness-reachable SDK/engine
locations on 4.4.3; only the harness-local copy resolved 4.6.7. The probe reports those retained
versions and relative locations before applying any refresh.

For that exact dependency set, this explicit consumer refresh produced 13 of 13 paths on 4.6.7:

```sh
npm install --save-exact --ignore-scripts --no-audit --no-fund zod@4.6.7
npm dedupe --ignore-scripts --no-audit --no-fund
```

This demonstrates a bounded refresh, not automatic remediation or a guarantee for arbitrary host
graphs. Inspect every relevant installed SDK/engine path, review and commit the consumer's lock
changes, and audit that application's graph separately. A retained affected copy is an unresolved
consumer case; the harness-local pin cannot make it pass.

## Regression evidence and remaining scope

Twenty-four handwritten cases use three elements with a declared bound of two. Value and map-key
callback counts stay zero on refusal; an input at the bound executes them. Array `.max`/`.length`,
set `.max`/`.size`, and map `.max`/`.size` cases pass through the interpreter, async interpreter,
strict compiled wrapper and standalone compiled function. The standalone compiler checks cannot
be satisfied by a compiler fallback. All six previous-4.4.3 interpreter cases fail the intended
callback-count assertion; no missing compilation API counts as a caught regression. The packed
helper control also refuses a fixed harness-local copy masking an affected shared SDK copy.

These controls establish no general resource bound for unconstrained schemas, checks preceded
by value-rewriting operations, other Zod APIs or host-owned validation paths. No advisory
suppression or reachability exception is requested. The remaining release gates named above
must pass before the draft is finalized.
[#161](https://github.com/Judgment-Pack/judgment-pack-agent/issues/161) remains undated upstream
follow-up outside v0.9.1; the withdrawn braces advisory is not a code remediation by this pin.
